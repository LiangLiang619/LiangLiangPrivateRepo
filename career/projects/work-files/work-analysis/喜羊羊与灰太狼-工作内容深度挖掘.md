## 三、平底锅道具深度分析

### 3.1 类继承与复用策略

```lua
local BP_PA_PR_PingDiGuoHammer = UE4.Class(
    "LetsGo.Script.Modplay.PlaceableActor.Prop.StarHammer.MoeStarHammer"
)
```

**选型理由：** `MoeStarHammer` 是近战锤子基类，已经封装好：

| 基类能力 | 说明 |
|---------|------|
| 挥舞动画 + 打击特效 | `SpawnStarHammerEmitter` / `SpawnStarHammerHitEmitter` |
| 攻击判定盒 Overlap | 触发 `HitActor` 回调，DS 侧权威判定 |
| Timer 生命周期管理 | `ClearAttackTimer` / `ClearMeleeBeginTimer` 等一套清理体系 |
| UGC 多次 spawn/destroy | 已适配对象池复用场景的基础生命周期 |
| 属性驱动 | `EmitterDelay`、`HitEmitterDelay`、`UseCoolTime` 均可配置 |

平底锅**只需覆写 3 个关键函数**（`UsePropImp`、`HitActor`、`ReceiveEndPlay`），不重写底层物理/判定逻辑。

### 3.2 双路命中通道设计

平底锅分两条路处理命中：

| 通道 | 函数 | 执行环境 | 职责 |
|------|------|---------|------|
| 击中他人 | `HitActor(OverlapActor)` | DS（HasAuthority） | 服务器权威；向被击中者发放 Buff；上报 GS 击中事件 |
| 命中自身（UGC 模式） | `UsePropHitSelf()` | Client（!HasAuthority） + DS | 客户端负责播放挥击动画；DS 延迟 0.1s 后为自身发放 Buff |

**客户端挥击动画（上半身混合）：**

```lua
function BP_PA_PR_PingDiGuoHammer:UsePropHitSelf()
    if not self:HasAuthority() then
        local AnimName = self.HitSelfAnimName or "AS_CH_Spring_Frying_Attack_001"
        local StateData = UE4.NewObject(UE4.UMoeCharActionStateCommonData)
        StateData.EnumCommonAction = _MOE.CommonDefine.ECommonActionName.PlayAnimation
        StateData.CustomString = UE4.rapidjson.encode({
            AnimName        = AnimName,
            SlotName        = "HandAction",
            bUpperBodyBlend = true   -- 上下半身混合，挥锅时仍可正常移动
        })
        Character:TryEnterActionState(UE4.ECharActionState.ActionCommon, StateData, false)
        return
    end
    -- DS 侧：0.1s 后给自己应用受击 Buff
    local timer = _MOE.TimerManager:AddTimer(0.1, self, function()
        self:ApplyHitBuffToSelf(cachedCharacter)
    end)
    self.delayHitSelfTimers[#self.delayHitSelfTimers + 1] = timer
end
```

### 3.3 对象池 / UGC 复用机制 — ReceiveEndPlay 关键防护

#### 问题背景

平底锅作为 UGC 道具，在对象池模式下会被**频繁 Spawn 和 Destroy**。某些路径下 Actor 对象被重用（Destroy 后再次进入 `OnRunningStateChanged → ResetToDefault` 流程）。

#### 崩溃链路

```
Actor Destroy
  → Lua ReceiveEndPlay
    → super MoeStarHammer:ReceiveEndPlay 中：
        self.WipeVelocityEffect        = nil   ← UnLua 反射，直接置空 C++ UPROPERTY(Instanced)
        self.AddImpulseEffect          = nil
        self.AddImpulseToPhysicEffect  = nil
  → Actor 被对象池取出复用
  → ResetToDefault() @ MoeStarHammer.cpp:41
    → 访问已被 nil 的 Instanced 指针
      → 空指针崩溃 💥
```

#### 解决方案：刻意跳过 super，手动执行必要清理

```lua
function BP_PA_PR_PingDiGuoHammer:ReceiveEndPlay()
    -- NOTE: 这里刻意不调用 super MoeStarHammer:ReceiveEndPlay
    -- 原因：base 里存在 self.WipeVelocityEffect / AddImpulseEffect / AddImpulseToPhysicEffect = nil
    -- 通过 UnLua 反射会把 C++ 侧 UPROPERTY(Instanced) 指针置空。
    -- PingDiGuoHammer 是 UGC 反复 spawn/destroy 的道具，若 EndPlay 后同 Actor 生命周期内
    -- 再次进入 OnRunningStateChanged → ResetToDefault 就会空指针崩溃
    -- （AMoeStarHammer::ResetToDefault() @ MoeStarHammer.cpp:41）。
    -- 因此这里手动执行 base ReceiveEndPlay 中的必要清理，跳过三个 Effect 的 nil 赋值。
    self:ClearAttackTimer()
    self:ClearMeleeBeginTimer()
    self:ClearMeleeAttackDurationTimer()
    self:ClearStarHammerEmitterTimer()
    self:ClearStarHammerHitEmitterTimer()
    self.EmitterRotationOffset = nil
    self.EmitterDirection = nil

    SkillButtonSlotData.SetValue(SkillButtonSlotData.EnumEventKey.bPingDiGuoIsHitSelf, false)
    self:ClearAllCachedTimers()
    self:K2_DestroyActor()
end
```

**核心结论：** 在 UnLua 与 UE 对象池组合场景下，`UPROPERTY(Instanced)` 成员不能在 `ReceiveEndPlay` 里被 Lua 反射置 nil；必须让子类跳过 super 调用，避免触发 C++ 侧的空指针崩溃。

### 3.4 快速使用防计时器覆盖（Timer 数组缓存）

**常规写法的问题：**

```lua
-- 问题：快速连续使用时，旧 timer 被新句柄覆盖，旧的命中丢失
self.delayTimer = _MOE.TimerManager:AddTimer(0.1, self, callback)
-- 第二次使用时：旧句柄丢失，旧命中的 callback 永远不会被 Remove
```

**平底锅的解法 — Timer 数组缓存：**

```lua
self.delayHitSelfTimers = self.delayHitSelfTimers or {}
local timer = _MOE.TimerManager:AddTimer(0.1, self, function()
    if not cachedCharacter or not UE4.UKismetSystemLibrary.IsValid(cachedCharacter) then
        return
    end
    self:ApplyHitBuffToSelf(cachedCharacter)
end)
self.delayHitSelfTimers[#self.delayHitSelfTimers + 1] = timer  -- 追加，不覆盖
```

**四组 Timer 分类管理，统一清理：**

```lua
function BP_PA_PR_PingDiGuoHammer:ClearAllCachedTimers()
    -- 1. delayHitSelfTimers    —— 命中自身延迟
    if self.delayHitSelfTimers then
        for _, timer in ipairs(self.delayHitSelfTimers) do
            _MOE.TimerManager:RemoveTimer(timer)
        end
        self.delayHitSelfTimers = nil
    end

    -- 2. delayHitEffectTimers  —— 命中特效延迟
    if self.delayHitEffectTimers then
        for _, timer in ipairs(self.delayHitEffectTimers) do
            _MOE.TimerManager:RemoveTimer(timer)
        end
        self.delayHitEffectTimers = nil
    end

    -- 3. addBuffDelayTimer     —— 新增 Buff 后的初始化延迟（单个）
    if self.addBuffDelayTimer then
        _MOE.TimerManager:RemoveTimer(self.addBuffDelayTimer)
        self.addBuffDelayTimer = nil
    end

    -- 4. delayOnHitPlayerTimer —— 命中他人特效延迟（单个）
    if self.delayOnHitPlayerTimer then
        _MOE.TimerManager:RemoveTimer(self.delayOnHitPlayerTimer)
        self.delayOnHitPlayerTimer = nil
    end
end
```

**Closure 变量捕获防野指针（每个 Timer 独立捕获当前帧对象）：**

```lua
local cachedCharacter = Character       -- 值捕获，与外部引用解耦
local timer = _MOE.TimerManager:AddTimer(0.1, self, function()
    -- Timer 触发时，外部 Character 变量可能已被重新赋值或失效
    -- 这里检查的是独立捕获的 cachedCharacter
    if not cachedCharacter or not UE4.UKismetSystemLibrary.IsValid(cachedCharacter) then
        return
    end
    self:ApplyHitBuffToSelf(cachedCharacter)
end)
```

### 3.5 四阶段受击效果状态机

受击效果由 `XiYangYangPingDiGuoConfig` 配置表驱动（按 ID 1~4 读取 `hitNumThreshold`、`bubbleText`、`bubbleDuration`）：

```
累积命中次数
  ├── == threshold[1] → hitEffectId = 1 → ShowBubble（气泡提示）
  ├── == threshold[2] → hitEffectId = 2 → BecomeChiikawaBodyType（变二头身）
  │                                     └─ 若已是 Chiikawa → EnterDizzyState（眩晕）
  ├── == threshold[3] → hitEffectId = 3 → ShowBubble
  └── == threshold[4] → hitEffectId = 4 → EnterPaiBianBuff（拍扁）
                                         → ShowBubble
                                         → RemoveSelfBuff（本 Buff 自销毁，达终态）
```

**Buff 刷新机制：** 同一玩家已有 `BP_Buff_HitByPingDiGuo` 时，调用 `hitBuff:IncreaseHitCount(buffKeepTime)` 累加次数并刷新持续时间，而不是重新 AddBuff（避免 HitTimes 重置）。

**状态保护黑名单：**

```lua
local ACTION_STATE_BLACKLIST = {
    UE4.ECharActionState.InteractAction,    -- 正在使用设施
    UE4.ECharActionState.GrabCharacter,     -- 正在抱人
    UE4.ECharActionState.InteractiveActor,  -- 正在交互
}
local MOTION_STATE_BLACKLIST = {
    UE4.ECharMotionState.BeGrabed,          -- 被人抱着
}
```

处于以上任意状态时，`IncreaseHitCount` 直接 return，不累加命中次数。

## 四、拍扁 Buff（BP_Buff_PaiBian）深度分析

### 4.1 视觉拍扁实现

```lua
-- 进入拍扁：Y 轴缩到 flattenScale（默认 0.2），同时 Z 轴旋转 90°
mesh:SetRelativeScale3D(UE4.FVector(originalScale.X, flattenScale, originalScale.Z))
mesh:K2_SetRelativeRotation(UE4.FRotator(originalRotation.Pitch, originalRotation.Yaw, 90))

-- 退出拍扁：精确恢复存储的原始值
mesh:SetRelativeScale3D(self.OriginalScale)
mesh:K2_SetRelativeRotation(self.OriginalRotation)
```

### 4.2 附属 Actor/Component Scale 缓存系统

拍扁时不只有角色主 Mesh 变形，**所有附加道具、手持物、Mesh 子 Component** 也需要同步缩放，退出时逐一恢复。

```lua
-- 缓存结构：区分 Actor（用 SetActorScale3D）和 Component（用 SetWorldScale3D）
local function CacheActorScale(records, actor)
    records[#records + 1] = {
        object = actor,
        scale  = CopyVector(actor:GetActorScale3D()),  -- 深拷贝，防引用污染
        isActor = true
    }
end

local function CacheComponentScale(records, component)
    records[#records + 1] = {
        object  = component,
        scale   = CopyVector(component:GetComponentScale()),
        isActor = false
    }
end

-- 恢复时按 isActor 分路处理
function BP_Buff_PaiBian:RestoreAttachedPropScaleRecords(bClearRecords)
    for _, record in ipairs(self.AttachedPropScaleRecords) do
        if IsValidObject(record.object) and record.scale then
            if record.isActor then
                record.object:SetActorScale3D(record.scale)
            else
                record.object:SetWorldScale3D(record.scale)
            end
        end
    end
    if bClearRecords then
        self.AttachedPropScaleRecords = nil
    end
end
```

**缓存时机：** 进入拍扁时缓存一次；退出时再缓存一次（覆盖，防止拍扁期间有附属物被动态添加/移除）。

### 4.3 物理强制关闭（Loop Timer 保险机制）

拍扁期间需完全关闭布料/骨骼物理，防止角色穿插/飞出。

**为什么需要 Loop Timer？**
- `PhysicsComponent` 会被多个系统（动画、碰撞事件、其他 Buff 等）反复开启
- 单次 `SetMeshPhysicsEnable(false)` 不够，需要循环强制维持

```lua
-- 每 0.5s 强制关一次物理
self.PhysicsCheckTimer = _MOE.TimerManager:AddLoopTimer(0.5, self, function()
    charPhysicsComponent.bForceDisablePhysics = true
    charPhysicsComponent.bEnablePhysics       = false
    charPhysicsComponent:SetMeshPhysicsEnable(false)
end)
```

**退出时双保险恢复：**

```lua
-- 第一次：Buff Remove 时立即恢复
charPhysicsComponent.bForceDisablePhysics = false
charPhysicsComponent:SetMeshPhysicsEnable(true)

-- 第二次：3s 后再恢复（防止同帧其他逻辑重新关闭）
self.DelayRestoreTimer = _MOE.TimerManager:AddTimer(3.0, self, function()
    charPhysicsComponent.bForceDisablePhysics = false
    charPhysicsComponent:SetMeshPhysicsEnable(true)
end)
```

### 4.4 手持物隐藏与恢复

```lua
-- 进入拍扁：强制隐藏手持物，锁定 HandHoldComponent
CharAvatarComponent.IsForceHideHandHold = true
CharAvatarComponent:SetHandHoldVisibility(false)
CharHandHoldComponent:SetIsInExtraState(true)  -- 进入特殊状态，阻止手持物刷新

-- 退出拍扁：解锁后延迟 0.12s 刷新手持物（等待 Mesh Scale 恢复稳定）
CharHandHoldComponent:SetIsInExtraState(false)

    CharAvatarComponent:UpdateHandHoldVisibility()

end)
```

### 4.5 禁止抱人（Buff Attribute 机制）


## 五、二头身 Buff（BP_Buff_ChiikawaBodyType）

### 5.1 AnimInstance 变量驱动体型

```lua
function BP_Buff_ChiikawaBodyType:ReceiveOnAddBuff()
    local animInstance = character:GetCharMesh():GetAnimInstance()
    animInstance.IsUse2Bodytype = true   -- 通知动画蓝图切换到二头身骨骼姿态
end

function BP_Buff_ChiikawaBodyType:ReceiveOnRemoveBuff()
    local animInstance = character:GetCharMesh():GetAnimInstance()
    animInstance.IsUse2Bodytype = false
end
```

### 5.2 换装刷新 AnimInstance 时的竞争处理

玩家换装会触发 `AnimInstance` 重建，重建后 `IsUse2Bodytype` 会被重置为默认值（false），导致二头身 Buff 视觉失效。

**解法：监听两个换装事件**

```lua
function BP_Buff_ChiikawaBodyType:ReceiveInit()
    -- 换装前：将 IsUse2Bodytype 先置 false，防止新 AnimInstance 拿到脏值
    _MOE.EventManager:RegisterEvent(
        _MOE.EventEnum.OnBeforeRefreshAnimInstance, self,
        self.OnBeforeRefreshAnimInstance
    )
    -- 换装后：如果 Buff 还在，重新开启 IsUse2Bodytype
    _MOE.EventManager:RegisterEvent(
        _MOE.EventEnum.OnRefreshAnimInstance, self,
        function(self, UID, BodyType)
            if UID == self.Target:GetUID() and BodyType ~= UE4.EMoeBodyType.Chiikawa then
                self:ReceiveOnAddBuff()   -- 重新触发，让新 AnimInstance 生效
            end
        end
    )
end
```

## 六、喷射道具 Spline/抛物线复用机制

### 6.1 复用冰冻手雷 Throw 组件

Wiki 方案："喷射道具复用类似冰冻手雷抛物线道具"。

系统中的 `MoeStickyBomb`（粘性炸弹）/ `IcePrincess`（冰杖） 类道具使用 **Throw 组件**进行抛物线投掷：

```
UE Blueprint 层：SplineComponent 预演抛物线轨迹（可视化预测线）
Lua 层：OnManipulateImp / BeforeThrowImp 控制发射逻辑
DS 层：SpawnActor 投射物，附着抛物线运动数据
```

关键接口（以 `MoeStickyBomb` 为例）：

```lua
-- 发射前：通知 DS 准备抛出
function MoeStickyBomb:BeforeThrowImp(throwComponent)
    self.stickBombSummoned:ServerBeforeThrow(throwComponent)
end

-- 施法计算：在发射起点 Spawn 投射物并绑定到角色
function MoeStickyBomb:OnManipulateImp(startLocation, direction, targetLocation)
    self.stickBombSummoned = world:SpawnActor(config.SummonClass,
        UE4.FTransform(UE4.FQuat(), startLocation, UE4.FVector(1, 1, 1)),
        UE4.ESpawnActorCollisionHandlingMethod.AlwaysSpawn)
    self.stickBombSummoned:SetOwner(characterOwner)
    self.stickBombSummoned:SetSummonInitInfo(characterOwner, self)
end

-- 获取 Throw 组件（用于 Spline 预测轨迹）
function MoeStickyBomb:GetCurrentThrowComponentsImp()
    return self.stickBombSummoned:GetThrowComponents()
end
```

### 6.2 喷汤圆/饺子道具的复用接入方式

喷射食物道具作为**新皮肤包装**套在同一套 Throw/Spline 体系上：

| 复用的内容 | 新增/替换的内容 |
|-----------|----------------|
| Spline 抛物线预测轨迹 | 投射物 Mesh（饺子/汤圆模型）|

| 道具次数/装配/丢弃系统 | 变身阈值读 `SpringFestivalHourseYearClientKVItem` KV 配置 |

## 七、食物受击变身 Buff（BP_Buff_HitByfSpringFestivalFood）

### 7.1 阈值倍数触发设计

```lua
-- 累积命中达到 hitThreshold 的倍数时触发变身
-- 允许 10次/20次/30次... 重复触发（每隔 threshold 次变身一次）
if self.HitTimes % hitThreshold ~= 0 then
```

默认阈值 10 次（可通过 KV 配置调整），设计目的是让玩家在被持续喷射时能多次变身。

### 7.2 变身 Buff 互斥保护（兼容华莱士联动）

```lua
function BP_Buff_HitByfSpringFestivalFood:HasAnyChangeAvatarBuff()
    if charBuffComponent:HasBuffByTag(JIAZI_BUFF_TAG) then return true end
    if charBuffComponent:HasBuffByTag(TANGYUAN_BUFF_TAG) then return true end
    if charBuffComponent:HasBuffByTag("BP_Buff_ChangeAvatar") then return true end  -- 华莱士
    return false
end
```

三重检查确保不会叠加多个变身 Buff，同时兼容历史版本华莱士联动的 Buff tag。

```lua
local NPCStateMutexTable = {
```

### 8.3 异步加载动画（防主线程卡顿）

```lua
-- 用 NPCId 作为 key，保证多个 NPC 独立加载互不干扰
self.npcAnimAsyncLoaders = self.npcAnimAsyncLoaders or {}

-- 新请求来时先 Cancel 旧 Loader
if self.npcAnimAsyncLoaders[NPCId] and self.npcAnimAsyncLoaders[NPCId]:IsValid() then
    self.npcAnimAsyncLoaders[NPCId]:CancelLoad()
    self.npcAnimAsyncLoaders[NPCId]["OnAssetLoadSuccess"]:Clear()
    self.npcAnimAsyncLoaders[NPCId]:Destroy()
end

self.npcAnimAsyncLoaders[NPCId] = _MOE.Utils.AssetLoadUtils.AsyncLoadAssetObject(
    animName,
    function(assetName, Animation)
        if assetName ~= cachedAnimName or not Animation then return end  -- 加载失败保护
        if not cachedActor or not UE4.UKismetSystemLibrary.IsValid(cachedActor) then
            return  -- Actor 已失效（中途切场景等）
        end

        local AnimLength = Animation.SequenceLength or 1
        cachedActor:PlayAnimationWithCallbackByAnimName(cachedAnimName, false)

        -- 动画结束后恢复 NPC 自身 Tick（IdleShow 展示逻辑）
        cachedActor.AnimTimers = cachedActor.AnimTimers or {}
        local Timer = _MOE.TimerManager:AddTimer(AnimLength, self, function()
            if cachedActor and UE4.UKismetSystemLibrary.IsValid(cachedActor) then
                cachedActor.m_SkipTick = false
            end
        end)
        table.insert(cachedActor.AnimTimers, Timer)
    end, self)
```

**为什么 `m_SkipTick = true`？** NPC 在非 Idle 状态下的自身 Tick 逻辑（巡逻、Idle 展示动画）会干扰彩蛋动画播放，通过这个标志位暂停 NPC 的自主 Tick，动画结束后再恢复。

## 十二、技术难点与踩坑记录

### 12.1 UGC 对象池 × UnLua 反射 × C++ UPROPERTY 三重冲突

**场景：** 平底锅作为 UGC 道具被对象池反复复用，Lua `ReceiveEndPlay` 中通过 UnLua 反射将 `UPROPERTY(Instanced)` 成员置 nil，导致 Actor 复用时 C++ `ResetToDefault` 空指针崩溃。

**解法：** 子类刻意跳过 super `ReceiveEndPlay`，手动执行必要清理逻辑，跳过危险的 nil 赋值。

**经验：** 在 UnLua 环境下，对 C++ 侧 `UPROPERTY(Instanced)` 指针成员执行 Lua nil 赋值时需谨慎，在对象池/复用场景下尤其危险。

### 12.2 快速连击导致 Timer 覆盖与命中丢失

**场景：** 平底锅快速连续使用时，若用单一 Timer 句柄，后一次 AddTimer 会覆盖前一次的句柄，导致前一次命中的延迟处理永远不会被 Remove（内存泄漏）且也不会执行（命中丢失）。

**解法：** 改用 `table` 数组缓存所有 Timer 句柄，`ReceiveEndPlay` 时统一遍历清理。

### 12.3 拍扁期间物理系统竞争

**场景：** 多个系统（动画事件、其他 Buff、碰撞回调）会在运行时重新开启物理，单次关闭物理不能持久。

**解法：** Loop Timer 每 0.5s 强制关闭一次，退出后延迟 3s 再次确保恢复。

### 12.4 二头身 AnimInstance 重建竞争

**场景：** 玩家换装触发 AnimInstance 重建，新实例的 `IsUse2Bodytype` 默认 false，导致二头身视觉瞬间消失。

**解法：** 监听 `OnBeforeRefreshAnimInstance`（重建前置 false）和 `OnRefreshAnimInstance`（重建后如果 Buff 还在则重新置 true）两个事件，确保换装后效果连续。

### 12.5 多 NPC 异步加载互相覆盖

**场景：** 彩蛋同时播放 3 个 NPC 的动画，若用单一 AsyncLoader 句柄，后续 NPC 的加载请求会覆盖前一个的句柄，导致前一个 Loader 无法 Cancel，回调可能在 Actor 失效后触发。

**解法：** 用 `npcAnimAsyncLoaders[NPCId]` 以 NPCId 为 key 独立管理，每次新请求先 Cancel 当前 NPC 自身的旧 Loader。

# 3C 角色动作状态与动画 · 面试话术汇总

> 用途：应对面试官"你处理过哪些 3C 角色动作状态与动画的内容"的提问。
> 依据：基于本人真实工作文档（平底锅、环绕物、走秀台、喜羊羊）梳理，全部可对应真实代码。
> 一句话结论：**状态侧从"进状态、读状态、写完整状态、状态多端同步"都做过；动画侧从"播动画、分层动画、体型适配"一直做到"改 AnimBP 的 BlendSpace 驱动机制"这种引擎层。**

---

## 一、把简历那句话拆成两半

- **角色动作状态** = ActionState / MotionState 状态机
- **动画** = AnimInstance / BlendSpace / Montage / 体型（BodyType）适配

## 二、我真正处理过的模块清单

### A. 角色动作状态（State）—— 5 类事

| 模块 | 具体做了什么（可讲） | 深浅 |
|---|---|---|
| **走秀玩家 Action State**（`MoeCharActionStateCommonZouXiu`） | **从头写了一个完整的角色动作状态**：注册 `ECommonActionName.ZouXiu` → 状态类 + StateData 蓝图；进入时批量置霸体（`CanGrab/CanBeGrab/CanDive/…=false`、`ForbiddenAddForce=true`）防打断；三段式 In/Show/Out；DS 权威准入；退出传送 + 收尾 | ⭐⭐⭐ 最硬 |
| **环绕物 idleShow 状态接入**（`UMoeCharActionStateIdleShow` Lua 覆写） | 覆写已有 Action State 的 `GetSurroundingsIdleShowSwitch/IsHitSurroundingsProbability/Enter/Exit`；**"首次必播、之后按概率"**；把演出决策（`CurrentIdleShowIdx`+概率结果）写进 **StateData 随状态同步**，保证主控端算一次、所有端表现一致 | ⭐⭐⭐ 含同步 |
| **平底锅命中自身进状态** | `Character:TryEnterActionState(ActionCommon, StateData)`，用 rapidjson 打包 StateData（AnimName/SlotName/上半身混合）驱动挥击动画；受击到阈值 `EnterDizzyState → ECharActionState.Dizziness` | ⭐⭐ |
| **状态互斥/黑名单判断** | 受击 Buff 读 `ECharActionState.InteractAction/GrabCharacter/InteractiveActor`、`ECharMotionState.BeGrabed` 做保护；环绕物按 `BlockedActionStates/BlockedMotionStates` 配表在特定状态隐藏 | ⭐⭐ |
| **监听状态机变更 + Motion State 读取** | 环绕物 `OnActionStateChanged/OnMotionStateChanged` 进出黑名单显隐；载具挂点靠读 `ECharMotionState.RideExclusiveVehicle/DriveExclusiveVehicle` 与 `ActionState.InteractiveActor` 切换 | ⭐⭐ |

### B. 动画（Animation）—— 5 类事

| 模块 | 具体做了什么 | 深浅 |
|---|---|---|
| **SeasonMoveBlendSpace 走秀走姿热替换**（本人产出 C++ 技术方案 wiki 4015671571） | **动画系统底层改造**：AnimBP 移动状态采样的是变量 `BSBaseMove`（`UBlendSpace1D*`）而非固定资产；在 `UMoeAnimStateComponent` 加 `SpecialMoveBlendSpaceNames` 数组 + `ChangeSpecialMoveBlendSpace`，在 `UMoeCharacterAnimInstance::UpdateBSBaseMoveByAvatarType` 加**最高优先级分支** `SetBSBaseMove(配表资源)`，运行时热替换默认跑步 BlendSpace、节日结束还原；Lua 封装 `ReplaceCommunitySeasonMoveBlendSpace` | ⭐⭐⭐ 最亮 |
| **上半身/全身分层动画** | 走路阶段上半身混合（`BlendTwoHands` + `PlaySlotAnimationAsDynamicMontage("HandAction")`，可边走边挥手飞吻）；表演阶段全身 pose（Montage） | ⭐⭐ |
| **二头身 AnimInstance 驱动 + 重建竞争** | `animInstance.IsUse2Bodytype = true` 通知 AnimBP 切二头身姿态；解决换装触发 AnimInstance **重建导致效果丢失**——监听 `OnBeforeRefreshAnimInstance`/`OnRefreshAnimInstance` 保证连续 | ⭐⭐ 有踩坑深度 |
| **体型（BodyType）动画适配** | 按体型加后缀（`GetAnimSuffixOfBodyType`，二头身/3.5头身/TM/TF/CKW/PD），走秀 BlendSpace、单双人动作都区分体型 | ⭐⭐ |
| **环绕物二期动画重构** | idleShow 从常驻 particle 改为 **mesh + 曲线（`UAnimTransformData` 离线烘焙 + 运行时 Lerp/Slerp 采样）** 驱动轨迹动画；核心逻辑 Lua 下沉自研 C++ | ⭐⭐⭐ 含 C++ |

## 三、面试怎么说（口播模板）

### 第 1 步：开场骨架（30 秒，先给结构）

> "角色动作状态与动画我主要在几个春节/国庆广场活动里做的。**动作状态**这块，我既有**读状态做逻辑**（比如受击时判断角色是否在被抱/交互状态做保护），也**完整写过角色的 Action State**——比如走秀，从状态注册、霸体控制、三段式流程到 DS 权威和退场都是我做的；还做过**状态附带数据的多端同步**。**动画**这块最有代表性的是我做的一套**走秀走姿的 BlendSpace 热替换机制**，是我出的 C++ 技术方案；另外还有上下半身分层动画、二头身体型适配这些。"

### 第 2 步：主打深挖故事（准备 2 个，一个动画一个状态）

#### 🎬 动画主打：SeasonMoveBlendSpace 走秀走姿热替换（王牌）

- **S（背景）**：走秀要让角色用"专属走姿"走路，且不能打滑、要随速度自适应，节日结束还得还原。
- **T（任务）**：在不改公共 AnimBP、不加节日专用分支（回归风险高）的前提下实现走姿替换。
- **A（做法）**："我发现 AnimBP 的移动状态采样的 BlendSpace 其实是一个**变量 `BSBaseMove`**，不是写死的资产。所以我在动画组件里加了一个**特殊行走 BlendSpace 优先级数组**，在 AnimInstance 更新 `BSBaseMove` 的地方插了一个**最高优先级分支**：只要数组非空就换成配表里的走秀走姿资产。这样运行时改一个变量，下一帧移动状态就采样到新 BlendSpace——**AnimBP 零改动、走的还是原生 Locomotion 速度混合链路所以不打滑、进出对称可还原**。我还封装了 Lua 接口，进走秀塞、退走秀移除，并按体型加后缀。"
- **R（结果）**：做成了通用机制，后续节日的特殊行走能直接复用。
- **为什么强**：证明你不是"调 PlayMontage 的 API"，而是**理解 AnimBP 的数据驱动本质、能改动画系统底层**。正是 3C 岗位想要的。

#### 🕹️ 状态主打（二选一）

**选项 1 —— 走秀 Action State（体现"完整实现一个状态"）**
> "走秀我写了一个完整的角色 Action State：注册到通用子动作状态里、带自己的 StateData。进入时要**霸体**——把抓取、扑、推挤、加力这些能力全部关掉，否则玩家走秀会被别人打断；然后是 In/表演/Out 三段式，DS 做权威准入（防多人同时上台的竞态），退出时传送到退场点并清理速度 Buff、还原动画。"

**选项 2 —— 环绕物 idleShow（体现"状态数据多端同步"，更能秀网络理解）**
> "环绕物的演出接在角色的 idleShow Action State 上。难点是'要不要演、演哪个'如果各端各自随机，同一个角色在不同人屏幕上就不一致。我的做法是**主控端算一次，把演出索引和概率命中结果写进状态的同步数据（StateData）里下发**，其他端直接读同步数据，保证多端表现一致。而且是'首次必播、之后按概率'。"

### 第 3 步：预判追问 + 弹药

| 面试官可能追问 | 怎么答（均来自真实代码） |
|---|---|
| "BlendSpace 热替换为什么不打滑？" | 因为没换动画驱动链路，只换了移动状态采样的资产变量，播放位置 X 仍由角色地面速度驱动，走的还是真实位移的速度混合。 |
| "为什么不用 Montage 覆盖走姿？" | Montage 会打滑、占 slot、和上半身玩梗动作冲突；变量热替换零改图、可配表、进出对称。 |
| "状态同步为什么不在各端本地算？" | 随机结果各端不一致会导致同一角色表现分裂，所以决策放主控端、结果随 StateData 同步。 |
| "二头身换装后为什么会失效，你怎么解决？" | 换装会重建 AnimInstance，新实例 `IsUse2Bodytype` 默认 false，我监听换装前后两个事件，重建后 Buff 还在就重新置回。 |
| "走秀怎么保证不被打断？" | 进状态即批量关闭 CanGrab/CanDive/CanBePush 等能力 + ForbiddenAddForce，即霸体。 |

## 四、关键提醒（别踩的坑）

1. **诚实分层**：走秀 Action State、SeasonMoveBlendSpace、环绕物是**独立写的**，可以说"我设计/实现"；平底锅的状态是**调用/进入**已有状态（`TryEnterActionState`），说"我用状态机的接口驱动了动画"，别说成"我实现了状态机框架"。面试官深挖底层（状态机怎么同步、SavedMove 那套）时，答"框架是引擎/公共层提供的，我在它之上做业务状态和动画"。
2. **区分"状态机框架" vs "业务状态"**：若被问"双状态机（Action/Motion）底层原理"（枚举分段偏移、`UMoeStateBase`、网络预测），答"我是它的使用者+扩展者"，然后把话题引回自己熟的走姿热替换和 idleShow 同步。
3. **动画那条是差异化**：很多候选人只会状态机 CRUD，能讲清"AnimBP 的 BlendSpace 是变量、可运行时热替换"的人不多，重点打这张牌。

## 五、底层知识补充（被追问 3C 引擎原理时的弹药）

> 说明：以下是项目 3C 框架（引擎/公共层）的原理，本人是**使用者 + 扩展者**，非框架作者。用于应对深挖。

- **双状态机为什么分两条**：Motion 管"怎么运动"、Action 管"在做什么"，正交并行，能叠加表达海量玩法组合。
- **状态枚举分段偏移**：uint8 只有 256 个不够，且要和网络协议保持数字兼容，所以分段 + 只在段尾追加 + `EStateIdOffsetType` 扩容。
- **CharacterMovement 网络预测**：客户端预测 + SavedMove 队列 + 服务器校验纠正 + 旁观端插值；难点在弱网下的纠正策略和"信客户端还是信服务器"的取舍。
- **手游 3C 第一约束是性能**：手动 Tick、Significance/LOD、角色对象池、服务器信任客户端跳过重算。

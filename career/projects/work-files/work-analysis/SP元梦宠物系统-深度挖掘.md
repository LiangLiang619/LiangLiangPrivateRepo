## 一、项目背景

SP 玩法（StarPal）内的**啾灵**作为第一批宠物种类打通至元梦广场，支持玩家带宠展示、骑乘与互动。

首版目标：
- 覆盖背包展示、召唤收回、行为 AI、骑乘、个人主页与图鉴等**完整链路**
- 对接 SP 侧解锁接口，处理**基础 / 焕彩 / 闪光 / 月卡临时**四类解锁规则
- 首批上线 **38+ 种**可带出啾灵，含 **1 款骑乘啾灵**

## 三、各模块详细设计

### 3.1 解锁规则

**三类啾灵解锁机制：**

- **基础啾灵**：购买过该啾灵的带出券（或 SP 月卡指定解锁），且在 SP 内捕获过；即使后来放了，也算解锁
- **焕彩啾灵**：对该啾灵使用过某个颜色的焕彩枪，则解锁对应焕彩版本
- **闪光啾灵**：捕到过该啾灵的闪光版本即解锁；解锁时自动拥有该啾灵所有**已解锁焕彩版本**的闪光版

**SP 月卡特殊处理：**
- 月卡解锁的啾灵属于**限时带出**，不计算时尚分
- 在背包中展示，月卡到期后从背包消失
- 在图鉴中仍为**未解锁**状态，不计入拥有数

**接口对接清单：**
1. 可带出啾灵 ID 列表接口（SP 侧提供）
2. 每个啾灵已解锁的焕彩版本 ID 列表接口
3. 每个啾灵是否解锁了闪光版本接口
4. 拿到啾灵 ID 后获取资源路径（模型、待机/表演/睡眠动画）
5. 拉起啾灵详情页接口（含页面分包处理）

### 3.2 背包 & UI 系统

**页签结构：**
```
背包
└── 宠物（bagType=11，subBagType=0）
    ├── 啾灵（subBagType=1）
    ├── 焕彩啾灵（subBagType=2）
    └── 闪光啾灵（subBagType=3）
```

**ICON 状态规则：**
- 稀有度底色：根据稀有度读取对应颜色底板
- 「新」角标：新获取的跟宠展示「新」，玩家点击后消失
- 排序规则：「新」状态优先，其次按品级降序，同品级按配置表 ID 升序
- 默认选中：每次进入界面默认选中第一个

**宠物选中展示：**
- 右侧展示选中宠物 3D 模型，定时随机播放一个待机动画（间隔同表演动画间隔）
- 展示名称、稀有度、道具介绍文本
- 放大：进入全屏界面展示模型与道具信息

**焕彩/闪光页签逻辑：**
- 根据基础页签选中的啾灵 ID，获取该啾灵所有已解锁焕彩/闪光信息
- 分别在对应页签展示；若某类解锁数为 0，显示默认空状态界面
- 选中某个焕彩后展示该焕彩样式，再次选中取消选择

**快捷操作栏：**
- 玩家拖拽啾灵至快捷操作栏（暂用载具栏位），大厅点击召唤
- 使用表情动作快捷栏，不新增、不使用载具栏位

**过期啾灵处理：**
- 解锁状态失效后，背包刷新后该啾灵消失
- 消失前已打开背包时，拖拽会提示「当前啾灵已失效」并刷新列表
- 若已在快捷召唤栏，清除对应状态

**骑乘可视标记：**
- 可骑乘啾灵图标左上角显示「可骑乘」
- 选中后右侧显示骑乘状态切换页签

### 3.3 召唤 & 收回

**召唤流程：**
1. 点击快捷交互栏（「召唤」页签，原「载具」页签改名）中已拖入的啾灵
2. 若当前已召唤同一只 → 收回；已召唤其他只 → 先收回再召唤新的
3. 无法召唤场景提示：「在当前场景无法召唤」

**可召唤场景（分版本）：**
- 首版：仅主广场
- 后续：星家园、农场、分广场

**不可召唤的角色状态：**
- 载具中 / 开火车 / 被抱起 / 使用坐椅 / 投篮机 / 旋转木马等

**自动收回触发：**
- 前往其他场景（农场、星家园、分广场）
- 前往其他玩家所在位置触发切换广场
- 广场合并 / 断线重连

> 注：玩家在召唤过程中，若啾灵可使用时限到期，不立即收回

**宠物大小：**
- 召唤时读取配置表中的缩放比例，进行缩放后召唤

**数量上限机制（关键设计）：**
- 场景宠物超过 10 只（可配置）上限时，新召唤的宠物标记为**仅自己可见**
- 当有宠物收回导致数量不足上限时，按召唤顺序将**最早召唤的仅自见宠物**升级为全员可见
- 分包未下完时：看不见他人宠物且无法互动；检测到需加载某宠物时下载对应分包

**立即使用功能：**
- 入口：恭喜获得啾灵界面 / 背包啾灵界面，均新增「立即使用」按钮
- 检测链路：场景是否可召唤 → 角色状态是否可召唤 → pak 是否下载完成 → 执行召唤
- 若成功召唤：关闭当前界面；若已召唤其他啾灵：先收回再召唤；若已召唤这只：收回并关闭界面

### 3.4 宠物行为 AI

**出生点规则：**
- 召唤时啾灵出生在**玩家角色朝向方向一定距离处**，伴随重生特效
- 若该位置无合法地形，在目标点附近寻找距玩家最近的合法地点（参考角色出生点逻辑）

**跟随行为三级距离参数：**

| 参数 | 含义 |
|------|------|
| Z（最大距离）| 超过则自动收回宠物并重新在玩家身边召唤 |
| X（寻路最大距离）| 超过该值则向玩家奔跑 |
| Y（待机范围）| 待机状态下只在玩家此范围内活动 |

**防卡死机制：**
- 宠物需向玩家移动但位置持续 2 秒未变化时，自动触发一次**瞬移到玩家身边**

**进入待机状态时：**
- 修改朝向，面向玩家方向

**气泡表情框：**

| ID | 触发时机 | 内容 |
|----|---------|------|
| 1 | 被召唤 | 文本或 SP 表情 ID |
| 2 | 进入待机状态 | 文本或 SP 表情 ID |
| 3 | 进入疾行状态 | 文本或 SP 表情 ID |
| 4 | 进入瞬移状态 | 文本或 SP 表情 ID |
| 5 | 进入睡觉状态 | 文本或 SP 表情 ID |
| 6 | 被抱起 | 文本或 SP 表情 ID |
| 7 | 随机触发 | 触发间隔：最小 2s，最大 5s |

> 气泡可限定特定啾灵种类触发，配置表驱动

**宠物名字显示：**
- 头顶显示宠物名字及所属玩家名字
- 遵从渐隐和隐藏规则，同名字版近大远小效果

**碰撞规则：**

| 碰撞对象 | 是否有碰撞 |
|---------|----------|
| 宠物 与 宠物 | 无碰撞 |
| 宠物 与 玩家 | 无碰撞 |
| 宠物 与 场景组件 | **有碰撞** |
| 宠物 与 道具 | 不受影响 |

**抱起互动：**
- 玩家可抱起**自己召唤**的宠物；尝试抱起他人宠物提示「无法抱起其他玩家的宠物」
- 被抱起后：朝向与玩家一致，与地面保持垂直，播放待机动作
- 抱起位置可调试（暂定：抱到头顶 或 抱在身前）
- 放下后宠物回到待机状态，行为同扔玩家
- 玩家抱起宠物时进入**不可被互动状态**（他人无法抱起该玩家或开火车）

**宠物信息面板：**
- 抱起宠物 或 点击宠物时弹出简介（骑乘态宠物只能点击）
- 点击「详情」弹出详情页，内容来自 `X_SP星兽配置表_主表` 的 SOC 配置表

### 3.5 骑乘系统

**两种状态：**
- **跟宠态**：缩小版啾灵，跟随玩家
- **骑乘态**：正常大小版本，玩家骑乘

**进入骑乘：**
1. 玩家靠近自己召唤的可骑乘宠物，出现交互按钮
2. 按钮优先级：高于开火车/场景组件开始，低于结束场景组件
3. 点击后：收回跟宠态 → 立即在玩家位置召唤骑乘宠物 → 玩家默认进入骑乘状态

**离开骑乘：**
- 再次点击交互按钮或结束骑乘：收回骑乘宠物 → 重新召唤跟宠态
- 触发自动收回的行为均会导致离开骑乘状态

**骑乘逻辑复用 SP 内部：**
- 包括技能、座位数量、载人规则等交互逻辑均直接复用
- 邀请同乘采用**载具的邀请方式**

**骑乘性能权重上限：**
- 场景内骑乘宠物 + 载具的性能权重总和超过 100（可配置）时提示：「当前场景骑乘宠物太多啦，请等等再尝试」

**骑乘宠物碰撞规则：**

| 碰撞对象 | 是否有碰撞 |
|---------|----------|
| 骑乘宠物 与 骑乘宠物 | **有碰撞** |
| 骑乘宠物 与 玩家 | **有碰撞** |
| 骑乘宠物 与 场景组件 | **有碰撞** |
| 骑乘宠物 与 道具 | 不受影响 |

> 骑乘相关资源（PAK）需进**底包**

### 3.6 个人主页展示

**入口：** 个人信息页 → 设置 → 修改展示动作

**宠物分页：**
- 与背包一致，包含基础/焕彩/闪光啾灵三个页签
- 宠物模型放置在角色旁，大小为缩放后大小
- 切换至该页签时检测 SP 分包是否下完，未下完弹窗提示

**骑乘展示（7.29 新增）：**
- 若选中啾灵存在骑乘态，右侧显示「跟随」和「骑乘」状态切换
- 「骑乘」态改为玩家骑乘状态展示，类似载具展示
- 可选择同乘玩家，功能与载具一致

**更换逻辑：**
- 在宠物分页选择使用后，修改个人主页展示内容
- 选择某个宠物但未点击使用返回时，弹出确认提示

**显示规则：**
- 显示选中的宠物并展示（默认待机动作）
- 打开他人主页，或因重新下包导致资源未下载时，该页面暂不显示啾灵
- 骑乘状态也同样展示

## 四、啾灵行为 AI 系统（技术深度分析）

### 4.1 行为树版本对比

| 对比维度 | V1（已弃用） | V2（当前通用） |
|---------|------------|--------------|
| 主文件 | `BT_PalCommon` | `BT_Pal_AIStateControl` |
| 复杂度 | 简洁 | 完整，含战斗/感知/休闲全部逻辑 |
| 大厅适用性 | 无战斗场景参考价值高 | 需剥离战斗/感知区逻辑 |
| 野生逻辑 | 无 | 包含，需注意解耦 |

> V1 虽已弃用，但大厅不含互动和战斗模块，V1 仍有参考价值

---

### 4.2 V1 行为树节点详解

**BlackBoard 变量：**

| 变量名 | 说明 |
|-------|------|
| OwnerPlayer | 所属角色引用 |
| DistanceToOwner | 与所属角色的距离 |
| SpeedState | 0=距离很远，1=距离中等，2=身边 |
| DefaultMoveSpeed | 默认移动速度 |

**主要节点：**

- **BTS_Pal_DetectDistance**（Tick Service）  
  获取 `DistanceToOwner`，对比配置最大/最小距离，设置 `SpeedState`

- **BTT_Pal_GoToPlayer**（不在身边时）  
  使用 AIMoveTo 将啾灵移动至玩家位置；`SpeedState=0`（很远）时速度设为 `DefaultMoveSpeed × 3`

- **BTT_Pal_ChangeFaceEmotion**（在身边时，仅 DS 执行）  
  设置表情 ID 为 0（普通脸），时长 9999s；调用 `USPGameMonsterFaceEmoteComponent`

- **动画 Selector**（在身边时）：
  1. `BTT_Pal_SetAnimIdleRandom`：设置随机 Idle 状态
  2. `BTT_Pal_StopMove`：停止移动
  3. Wait 4 秒
  4. `BTT_Pal_Wander`：判断是否在水中 → 随机可达点 → AdvancedMoveToLocationOrActor

- **BTD_Pal_CheckCanSleep**：概率 0.3，冷却 15s，判断能否进入睡眠

### 4.3 V2 行为树节点详解

**大厅所需逻辑路径：**  
`休闲 → 伙伴休闲行为 → 伙伴跟随（BT_Pal_Relax_CompanionFollow_FollowExpPos）`

#### 定点跟随 Sequence

**BTT_Pal_UpdateKeepFromMasterParam**  
- 计算啾灵与玩家的最优伴随距离，结果存入黑板 `KeepFromMasterDistance`

**BTT_Pal_RefreshFollowMasterSpeedEnum**  
- 通过 `USPSwimComponent` 判断是否游泳，设置移动速度枚举：
  - `FollowSprintSwim` / `FollowSprint` / `FollowSwim` / `FollowWalk`

**UBTTask_AdvancedMoveTo（C++ 定义，继承 UBTTask_MoveTo）**  
- 额外参数：FlyingHeight、WaterSurfaceOffsetKey、RemainHealthRatio（半径范围）、StarPalFollowExpPos
- 并行 Service：持续刷新跟随速度

**等待 1s 后转向 Master**  
- 黑板值 `ShouldFollowMaster` 设置为 false
- `BTD_Pal_CheckShouldToFollowMaster.lua` 检查后等待 1s
- `BTT_Pal_RotateOnSpot.lua`：Tick 中实现平滑旋转

---

#### 野生休闲 BT_Pal_Relax_Wild_Branch（大厅睡眠/表演/待机内容在此处）

> 此节点设置 ForceSuccess

**休闲状态初始化：**
- 上报数据
- 切换为普通表情
- 设置 UI 表情
- 设置默认行走速度
- 进入飞行状态（如为飞行星兽）

**Loop Selector Service：BTS_Pal_UpdateSleepCondition_Native**  
- Tick 间隔 1 秒
- 根据配置获得睡眠时间段，判断当前时间是否可睡眠
- 修改黑板 `Relax_Wild_Condition_GoToSleep` 和 `CanInterruptAnim`

#### 特殊表演 BT_Pal_Relax_SpecialPerformanceShow_Behavior

**可表演判断（BTD_Pal_CheckMonsterHasSpecialPerformanceShow.lua）：**
- 根据配置的表演 stage + 啾灵自身是否有 1/2 阶段表演 + 关卡信号量

**表演基本流程：**  
`获得表演信息 → 移动到表演点 → 转向到表演点 → 播放表演`

**BTT_Pal_SetupSpecialPerformanceInfo：**
- 读取 ownerMonster 中当前表演阶段的表演 ID
- 将技能 ID、技能位置、技能转向存入黑板：`TempSkillId` / `TempVector` / `TempRotation`

**BTT_Pal_PlaySkillById：**
- 从黑板拿 `TempSkillId`
- 在 AbilityComponent 注册表演结束回调
- 调用 `AbilityComponent.TryActivateAbility` 激活技能（播放动画）

#### 睡眠子树 BT_Pal_Relax_Sleep_Branch

**BTD_Pal_SleepCoolDown：**
- 确保 `Relax_Wild_Condition_GoToSleep` 为 true
- 从 MonsterBase 拿冷却时间，判断上次成功到现在是否超过冷却

**大厅适配注意：** 睡眠 CD 结束时的感知区恢复逻辑（`ReceiveExecutionFinishAI` 中设置感知的部分）需屏蔽

**陆地睡眠流程：**
1. `BTD_Pal_CheckCanSleep.lua`：检查是否可睡觉
2. `UBTT_Pal_PlayAnimBySkillSlot_Native`：根据配置动画播放
3. 设置动作为可打断
4. 睡眠结束后恢复感应区

**飞行睡眠流程：**
1. 从配置表读取下降高度
2. `BTD_Pal_CheckActorLocationAreaType`：检查脚下是否为允许陆地
3. `BTT_Pal_SetSPMotionState`：进入 SP_Monster_Flying_Exit 状态（事件结束）
4. `UBTT_Pal_PlayAnimBySkillSlot_Native`：播放睡眠动画
5. 睡眠结束 → 恢复感应区 → `BTT_Pal_SetSPMotionState` 进入 FlyingEnter 状态

## 六、关键技术挑战与解决方案

### 挑战 1：宠物数量上限与可见性分层

**问题：** 广场有大量玩家同时召唤宠物时，性能压力极大。

**解决方案：**
- 设定场景宠物上限（默认 10 只，可配置）
- 超限后新召唤宠物标记为「仅自己可见」，不同步到其他客户端
- 有宠物被收回时，按召唤顺序将最早的「仅自见」宠物升级为全员可见
- 实现感知完全无感，用户体验不受影响

---

### 挑战 2：行为树大厅适配：战斗逻辑解耦

**问题：** V2 行为树为完整玩法设计，含大量战斗/感知区逻辑，大厅不需要但耦合难以直接剥离。

**解决方案：**
- 只复用 `休闲 → 伙伴休闲行为 → 伙伴跟随` 和 `野生休闲` 子树
- 屏蔽需处理的逻辑：
  - 睡眠 CD 结束时 `ReceiveExecutionFinishAI` 中的感知区恢复
  - `BestThreat` 黑板值的战斗判断逻辑
- 确保 `BestThreat` 在大厅始终为 null

---

### 挑战 3：骑乘切换资源热替换

**问题：** 进入/退出骑乘需要切换两种完全不同的资源（幼态缩小版 vs 正常版），要求无感知。

**解决方案：**
- 进入骑乘时：先收回跟宠态 → 立即在玩家所在位置召唤骑乘宠物 → 玩家自动进入骑乘状态
- 退出骑乘时：收回骑乘宠物 → 重新执行一次召唤（跟宠态）
- 骑乘宠物资源进底包，保证召唤时资源一定已就绪

---

### 挑战 4：解锁规则复杂建模

**问题：** 三类解锁规则（基础/焕彩/闪光）+ 月卡临时解锁，状态间有依赖关系。

**解决方案：**
- 分离「解锁状态」和「可带出状态」的概念
- 月卡解锁单独标记：带出功能可用，但不计时尚分、不计图鉴拥有数
- 闪光解锁时自动继承所有已解锁焕彩版本的闪光版，通过接口批量返回
- 统一通过 SP 提供的接口获取解锁状态，元梦侧只做消费

---

### 挑战 5：DS 同步与边界情况

**问题：** 宠物召唤/收回/表情等需 DS 广播，多种边界情况下状态需要一致。

**边界情况清单：**
- 中途加入广场：需正确显示已存在的宠物
- 广场合并：合并后宠物状态需同步
- 切前后台：宠物状态需正确恢复
- 断线重连：宠物是否保持召唤状态需明确（重连时自动收回）

**解决思路：**
- 出生点逻辑参考角色出生点的合法位置寻点
- 仅自见宠物的升级逻辑在服务端维护召唤顺序队列

## 一、需求背景与定位

### 1.1 设计目标

平底锅是春节广场联动的 **专属玩法道具**，核心设计目标：

- 强 IP 名场面致敬（灰太狼用平底锅敲喜羊羊）
- 可传播的社交互动点（被拍扁的滑稽视觉效果）
- 广场自由度互动：任意玩家之间均可使用，无需组队

### 1.2 两项子需求

| 子需求 | 估时 | 说明 |
|--------|------|------|
| 道具投放（道具有效时长通用能力） | 0.5 人天 | 广场投放现有机制直接支持；有效时长（5min 后消失）需作为通用能力新增 |
| 平底锅能力（受击 Buff + 变身体系） | 1 人天 | 近战敲击 + 4 阶段受击效果 |

### 1.3 受击效果策划原文

```
受击方累计次数（受击方需要有特效）
  敲击  1 次 → 气泡："好像有怪事要发生"
  敲击 10 次 → 脑袋晕眩状
  敲击 11 次 → 气泡："啊，要被变扁了"
  敲击 20 次 → 变成扁扁一片 + 气泡："变成了扁扁的一片"

解除变身：
  - 被变身的玩家耗时 5min 后自动恢复原始体型，头顶冒泡"哦~恢复原来的样子了"
  - 可通过：解除变身按钮、重置按钮、自杀、加入游戏、切换场景等解除
  - 变身时不能与广场设施互动，但可以自由移动
```

## 三、道具主体（BP_PA_PR_PingDiGuoHammer）深度分析

### 3.1 类继承与复用策略

```lua
local BP_PA_PR_PingDiGuoHammer = UE4.Class(
    "LetsGo.Script.Modplay.PlaceableActor.Prop.StarHammer.MoeStarHammer"
)
```

**选型理由：** `MoeStarHammer` 是近战锤子基类，已完整封装：

| 基类能力 | 说明 |
|---------|------|
| 挥舞动画 + 打击特效 | `SpawnStarHammerEmitter` / `SpawnStarHammerHitEmitter` |
| 攻击判定盒 Overlap | 触发 `HitActor` 回调，DS 侧权威判定 |
| Timer 生命周期管理 | `ClearAttackTimer` / `ClearMeleeBeginTimer` / `ClearMeleeAttackDurationTimer` 等 |
| 道具属性配置 | `HitEmitterDelay`、`UseCoolTime`、`EmitterRotationOffset` 均可蓝图配置 |
| UGC 多次 spawn/destroy | 已适配广场道具池基础生命周期 |

**平底锅只需覆写 5 个函数：**
- `UsePropImp` —— 重置使用 CD，非权威端上报 TDM
- `UsePropHitSelf` —— 命中自身模式（新增功能）
- `HitActor` —— 命中他人时发放受击 Buff + 上报 GS
- `GetLeftCDTimeImp` —— 自定义 CD 计算（取两路 CD 中较大值）
- `ReceiveEndPlay` —— 刻意跳过 super（防崩溃，见第五节）

### 3.2 双路命中通道设计

平底锅支持两条命中路径：

| 通道 | 函数 | 执行环境 | 职责 |
|------|------|---------|------|
| 命中他人 | `HitActor(OverlapActor)` | DS（HasAuthority） | 服务器权威判定；向被击中者发放 Buff；上报 GS 击中/拍扁事件 |
| 命中自身（UGC） | `UsePropHitSelf()` | Client + DS | 客户端负责播放挥击动画；DS 延迟 0.1s 后为自身发放 Buff |

**命中自身 —— 客户端播放上半身混合动画：**

```lua
function BP_PA_PR_PingDiGuoHammer:UsePropHitSelf()
    if not self:HasAuthority() then
        -- 播放命中自身动画（上下半身混合，挥锅时仍可正常移动）
        local AnimName = self.HitSelfAnimName or "AS_CH_Spring_Frying_Attack_001"
        local StateData = UE4.NewObject(UE4.UMoeCharActionStateCommonData)
        StateData.EnumCommonAction = _MOE.CommonDefine.ECommonActionName.PlayAnimation
        StateData.CustomString = UE4.rapidjson.encode({
            AnimName        = AnimName,
            SlotName        = "HandAction",
            bUpperBodyBlend = true
        })
        Character:TryEnterActionState(UE4.ECharActionState.ActionCommon, StateData, false)
        return
    end
    -- DS 侧：延迟 0.1s 给自己应用受击 Buff
    local cachedCharacter = Character
    local timer = _MOE.TimerManager:AddTimer(0.1, self, function()
        if not cachedCharacter or not UE4.UKismetSystemLibrary.IsValid(cachedCharacter) then
            return
        end
        self:ApplyHitBuffToSelf(cachedCharacter)
    end)
    self.delayHitSelfTimers[#self.delayHitSelfTimers + 1] = timer
end
```

**命中他人 —— DS 权威处理完整流程：**

```lua
function BP_PA_PR_PingDiGuoHammer:HitActor(OverlapActor)
    -- 1. 获取受击方的 Buff 组件
    local buffComp = OverlapActor:GetCharBuffComponent()
    local buffKeepTime = tonumber(
        _MOE.Config.SpringFestivalHourseYearClientKVItem:GetSpringFestivalKVByKey("PingDiGuoHitBuffDuration")
    ) or 180

    -- 2. 延迟播放命中特效（等挥击动画同步到位）
    local cachedOverlapActor = OverlapActor
    self.delayOnHitPlayerTimer = _MOE.TimerManager:AddTimer(delayTime, self, function()
        self:OnHitPlayer(cachedOverlapActor)
    end)

    -- 3. 发放受击 Buff（已有则增加次数，没有则新建）
    local hitBuff = buffComp:GetBuffByTag("BP_Buff_HitByPingDiGuo")
    if hitBuff then
        -- 预判下次命中是否触发拍扁（用于上报）
        if hitBuff:IfEnterPaiBianBuff() then
            _MOE.CommunityReportUtil.ReportLobbyEventToGS(
                _MOE.CommunityReportUtil.EnumReportPath.DSToGS, UID,
                _MOE.ServerEnum.BattleEventType.BET_LOBBY_FRYING_PAN_FLATTEN, 1
            )
        end
        hitBuff:IncreaseHitCount(buffKeepTime)
    else
        buffComp:AddBuffLua("BP_Buff_HitByPingDiGuo", buffKeepTime, true)
        local newHitBuff = buffComp:GetBuffByTag("BP_Buff_HitByPingDiGuo")
        if newHitBuff then
            newHitBuff:IncreaseHitCount(buffKeepTime)
        end
    end

    -- 4. 上报击中事件到 GS
    _MOE.CommunityReportUtil.ReportLobbyEventToGS(
        _MOE.CommunityReportUtil.EnumReportPath.DSToGS, UID,
        _MOE.ServerEnum.BattleEventType.BET_LOBBY_FRYING_PAN_HIT, 1
    )
end
```

## 四、受击累计 Buff（BP_Buff_HitByPingDiGuo）

### 4.1 四阶段状态机

受击效果由 `XiYangYangPingDiGuoConfig` 配置表驱动（按 ID=1~4 读取 `hitNumThreshold`、`bubbleText`、`bubbleDuration`）：

```
累积命中次数（HitTimes）
    │
    ├── == threshold[1]（默认 1 次）
    │   → hitEffectId = 1
    │   → ShowBubble（"好像有怪事要发生"）
    │
    ├── == threshold[2]（默认 10 次）
    │   → hitEffectId = 2
    │   → 判断当前体型：
    │       非 Chiikawa → BP_Buff_ChiikawaBodyType（变二头身）
    │       已是 Chiikawa → EnterDizzyState（进入晕眩 State）
    │   → ShowBubble（"脑袋晕眩状"）
    │
    ├── == threshold[3]（默认 11 次）
    │   → hitEffectId = 3
    │   → ShowBubble（"啊，要被变扁了"）
    │
    └── == threshold[4]（默认 20 次）
        → hitEffectId = 4
        → EnterPaiBianBuff（进入拍扁 Buff）
        → ShowBubble（"变成了扁扁的一片"）
        → RemoveSelfBuff（Buff 自销毁，HitTimes 重置归零）
```

**关键设计决策——配置驱动而非硬编码：**

```lua
function BP_Buff_HitByPingDiGuo:TryAddChangeAvatarBuff()
    for i = 1, 4 do
        local config = _MOE.Config.XiYangYangPingDiGuoConfig:GetPingDiGuoConfigById(i)
        local threshold = config and config.hitNumThreshold
        -- 精确相等匹配，不是大于等于
        -- 好处：每个阈值只触发一次，支持热更调整阈值
        if threshold and self.HitTimes == threshold then
            self:HandleHitEffect(i, config)
            return
        end
    end
end
```

### 4.2 Buff 次数累积而非重建

同一玩家身上已有受击 Buff 时，**不移除重建**，而是直接累加次数并刷新持续时间：

```lua
-- 道具端（BP_PA_PR_PingDiGuoHammer:HitActor）
local hitBuff = buffComp:GetBuffByTag("BP_Buff_HitByPingDiGuo")
if hitBuff then
    hitBuff:IncreaseHitCount(buffKeepTime)  -- 累加 + 刷新时长
else
    buffComp:AddBuffLua("BP_Buff_HitByPingDiGuo", buffKeepTime, true)
    hitBuff = buffComp:GetBuffByTag("BP_Buff_HitByPingDiGuo")
    if hitBuff then
        hitBuff:IncreaseHitCount(buffKeepTime)
    end
end

-- Buff 端（BP_Buff_HitByPingDiGuo:IncreaseHitCount）
function BP_Buff_HitByPingDiGuo:IncreaseHitCount(keepTime)
    self.HitTimes = (self.HitTimes or 0) + 1
    -- 每次命中都刷新 Buff 持续时间，防止统计窗口在 BuffDuration 内过期
    if keepTime and keepTime > 0 then
        self:SetKeepTime(keepTime)
    end
    self:TryAddChangeAvatarBuff()
end
```

**为什么不移除重建？** 移除 Buff 会将 `HitTimes` 重置为 0，导致次数累积断开。

### 4.3 状态保护黑名单

处于以下状态时，`IncreaseHitCount` 直接 return，不累加命中次数：

```lua
-- Action State 黑名单：正在使用设施/抱人/交互中
local ACTION_STATE_BLACKLIST = {
    UE4.ECharActionState.InteractAction,
    UE4.ECharActionState.GrabCharacter,
    UE4.ECharActionState.InteractiveActor,
}

-- Motion State 黑名单：正在被人抱着
local MOTION_STATE_BLACKLIST = {
    UE4.ECharMotionState.BeGrabed,
}
```

### 4.4 拍扁触发前预判（供上报使用）

`IfEnterPaiBianBuff` 被道具端 `HitActor` 调用，用于在实际触发前预判此次命中是否会引发拍扁，从而提前上报 GS：

```lua
function BP_Buff_HitByPingDiGuo:IfEnterPaiBianBuff()
    -- 预判：如果当前次数 +1 == threshold[4]，则会触发拍扁
    local hitTimes = (self.HitTimes or 0) + 1
    local config = _MOE.Config.XiYangYangPingDiGuoConfig:GetPingDiGuoConfigById(4)
    local threshold = config and config.hitNumThreshold
    return threshold and hitTimes == threshold
end
```

## 五、UGC 对象池 × UnLua 反射崩溃防护

### 5.1 问题背景

平底锅作为 UGC 道具，在广场道具系统中会被**频繁 Spawn 和 Destroy**（甚至对象池复用）。

C++ `MoeStarHammer::ReceiveEndPlay` 中存在通过 UnLua 反射将 `UPROPERTY(Instanced)` 指针置 nil 的代码：

```cpp
// MoeStarHammer.cpp 对应的 Lua base 逻辑
self.WipeVelocityEffect       = nil  -- UnLua 反射，直接修改 C++ UPROPERTY(Instanced)
self.AddImpulseEffect         = nil
self.AddImpulseToPhysicEffect = nil
```

### 5.2 崩溃链路

```
Actor K2_DestroyActor
  → Lua ReceiveEndPlay（如果调用 super）
    → MoeStarHammer:ReceiveEndPlay 中将三个 UPROPERTY(Instanced) 置 nil
  → Actor 被对象池取出复用
  → AMoeStarHammer::ResetToDefault() @ MoeStarHammer.cpp:41
    → 访问已被置 nil 的 Instanced 指针
      → 空指针崩溃 💥
```

### 5.3 解法：刻意跳过 super，手动执行必要清理

```lua
function BP_PA_PR_PingDiGuoHammer:ReceiveEndPlay()
    -- NOTE: 这里刻意不调用 super MoeStarHammer:ReceiveEndPlay
    -- 原因：base 里存在 self.WipeVelocityEffect / AddImpulseEffect / AddImpulseToPhysicEffect = nil
    -- 通过 UnLua 反射会把 C++ 侧 UPROPERTY(Instanced) 指针置空。
    -- PingDiGuoHammer 是 UGC 反复 spawn/destroy 的道具，若 EndPlay 后同 Actor 生命周期内
    -- 再次进入 OnRunningStateChanged → ResetToDefault 就会空指针崩溃
    -- （AMoeStarHammer::ResetToDefault() @ MoeStarHammer.cpp:41）。
    -- 因此这里手动执行 base ReceiveEndPlay 中的必要清理，跳过三个 Effect 的 nil 赋值。
    self:ClearAttackTimer()
    self:ClearMeleeBeginTimer()
    self:ClearMeleeAttackDurationTimer()
    self:ClearStarHammerEmitterTimer()
    self:ClearStarHammerHitEmitterTimer()
    self.EmitterRotationOffset = nil
    self.EmitterDirection = nil

    SkillButtonSlotData.SetValue(SkillButtonSlotData.EnumEventKey.bPingDiGuoIsHitSelf, false)
    self:ClearAllCachedTimers()
    self:K2_DestroyActor()
end
```

**核心经验：** 在 UnLua 与 UE 对象池组合场景下，`UPROPERTY(Instanced)` 成员不能在 `ReceiveEndPlay` 里被 Lua 反射置 nil；必须让子类跳过 super 调用，手动实现必要清理，规避 C++ 侧空指针崩溃。

## 六、快速连击防 Timer 覆盖

### 6.1 问题

平底锅可以快速连续使用（CD 仅 0.5s），若使用单一 Timer 句柄，后一次 `AddTimer` 会覆盖前一次句柄：

```lua
-- 问题写法：快速使用两次时，第一次命中的 timer 句柄被第二次覆盖
self.delayTimer = _MOE.TimerManager:AddTimer(0.1, self, callback)
-- 第二次 AddTimer 后，第一次的 timer 句柄丢失，第一次命中的 callback 不会执行
```

### 6.2 解法：Timer 数组缓存

```lua
-- 正确写法：用数组追加，不覆盖
self.delayHitSelfTimers = self.delayHitSelfTimers or {}
local cachedCharacter = Character   -- 值捕获，与外部引用解耦
local timer = _MOE.TimerManager:AddTimer(0.1, self, function()
    -- 闭包中检查各自捕获的对象是否仍然有效
    if not cachedCharacter or not UE4.UKismetSystemLibrary.IsValid(cachedCharacter) then
        _MOE.Logger.LogWarning("timer callback: Character is no longer valid")
        return
    end
    self:ApplyHitBuffToSelf(cachedCharacter)
end)
self.delayHitSelfTimers[#self.delayHitSelfTimers + 1] = timer  -- 追加，不覆盖
```

### 6.3 四组 Timer 分类管理

```lua
function BP_PA_PR_PingDiGuoHammer:ClearAllCachedTimers()
    -- 1. delayHitSelfTimers    —— 命中自身延迟（数组，可能多个）
    if self.delayHitSelfTimers then
        for _, timer in ipairs(self.delayHitSelfTimers) do
            _MOE.TimerManager:RemoveTimer(timer)
        end
        self.delayHitSelfTimers = nil
    end

    -- 2. delayHitEffectTimers  —— 命中特效延迟（数组，可能多个）
    if self.delayHitEffectTimers then
        for _, timer in ipairs(self.delayHitEffectTimers) do
            _MOE.TimerManager:RemoveTimer(timer)
        end
        self.delayHitEffectTimers = nil
    end

    -- 3. addBuffDelayTimer     —— 新增 Buff 后的初始化延迟（单个）
    if self.addBuffDelayTimer then
        _MOE.TimerManager:RemoveTimer(self.addBuffDelayTimer)
        self.addBuffDelayTimer = nil
    end

    -- 4. delayOnHitPlayerTimer —— 命中他人特效延迟（单个）
    if self.delayOnHitPlayerTimer then
        _MOE.TimerManager:RemoveTimer(self.delayOnHitPlayerTimer)
        self.delayOnHitPlayerTimer = nil
    end
end
```

## 七、拍扁 Buff（BP_Buff_PaiBian）深度分析

### 7.1 视觉拍扁实现

```lua
-- 进入拍扁：Y 轴缩到 flattenScale（默认 0.2），同时 Z 轴旋转 90°
local flattenScale = self.flattenScale or 0.2
mesh:SetRelativeScale3D(UE4.FVector(self.OriginalScale.X, flattenScale, self.OriginalScale.Z))
mesh:K2_SetRelativeRotation(UE4.FRotator(self.OriginalRotation.Pitch, self.OriginalRotation.Yaw, 90))

-- 退出拍扁：精确恢复存储的原始值（进入时缓存的深拷贝）
mesh:SetRelativeScale3D(self.OriginalScale)
mesh:K2_SetRelativeRotation(self.OriginalRotation)
```

### 7.2 附属 Actor/Component Scale 缓存系统

拍扁时不只有角色主 Mesh 变形，**所有附加道具、手持物、Mesh 子 Component** 也随之缩放，退出时逐一恢复：

```lua
function BP_Buff_PaiBian:CacheAttachedPropScaleRecords(character, mesh)
    self.AttachedPropScaleRecords = self.AttachedPropScaleRecords or {}

    -- 缓存所有 AttachedActors 的 Scale
    local attachedActors = character:GetAttachedActors()
    if attachedActors then
        for index = 1, attachedActors:Length() do
            CacheActorScale(self.AttachedPropScaleRecords, attachedActors:GetRef(index))
        end
    end

    -- 额外缓存手持物 Actor
    local charAvatarComponent = character:GetMoeCharAvatarComponent()
    local handHoldActor = charAvatarComponent and charAvatarComponent:GetHandHoldLightBP()
    CacheActorScale(self.AttachedPropScaleRecords, handHoldActor)

    -- 缓存 Mesh 子 Component
    local attachChildren = mesh:GetAttachChildren()
    if attachChildren then
        for index = 1, attachChildren:Length() do
            CacheComponentScale(self.AttachedPropScaleRecords, attachChildren:GetRef(index))
        end
    end
end
```

**缓存结构设计（区分 Actor 和 Component 两类接口）：**

```lua
-- Actor 类：用 GetActorScale3D / SetActorScale3D
local function CacheActorScale(records, actor)
    if not IsValidObject(actor) or HasCachedObject(records, actor) then return end
    local scale = CopyVector(actor:GetActorScale3D())  -- 深拷贝，防引用污染
    records[#records + 1] = { object = actor, scale = scale, isActor = true }
end

-- Component 类：用 GetComponentScale / SetWorldScale3D
local function CacheComponentScale(records, component)
    if not IsValidObject(component) or HasCachedObject(records, component) then return end
    local scale = CopyVector(component:GetComponentScale())
    records[#records + 1] = { object = component, scale = scale, isActor = false }
end
```

**缓存时机：** 进入拍扁时缓存一次；退出拍扁时再缓存一次（覆盖），防止拍扁期间有附属物被动态添加或移除。

### 7.3 物理强制关闭（Loop Timer 保险）

拍扁期间需完全关闭布料/骨骼物理，防止角色穿插或飞出。

**为什么需要 Loop Timer？**
- `PhysicsComponent` 会被动画系统、碰撞事件、其他 Buff 等多处逻辑反复开启
- 单次 `SetMeshPhysicsEnable(false)` 不能持久维持
- 需要循环强制覆盖，保证拍扁状态下物理始终关闭

```lua
-- 每 0.5s 强制关一次物理
self.PhysicsCheckTimer = _MOE.TimerManager:AddLoopTimer(0.5, self, function()
    self:DisablePhysics()
end)

function BP_Buff_PaiBian:DisablePhysics()
    local charPhysicsComponent = character:GetComponentByClass(UE4.UMoeCharPhysicsComponent)
    if charPhysicsComponent then
        charPhysicsComponent.bForceDisablePhysics = true
        charPhysicsComponent.bEnablePhysics       = false
        charPhysicsComponent:SetMeshPhysicsEnable(false)
    end
end
```

**退出拍扁时双保险恢复：**

```lua
-- 第一次：Buff Remove 时立即恢复
charPhysicsComponent.bForceDisablePhysics = false
charPhysicsComponent:SetMeshPhysicsEnable(true)
charPhysicsComponent.bEnablePhysics = true

-- 第二次：3s 后再恢复（防止同帧其他逻辑重新关闭）
self.DelayRestoreTimer = _MOE.TimerManager:AddTimer(3.0, self, function()
    self.DelayRestoreTimer = nil
    if not cachedCharacter or not UE4.UKismetSystemLibrary.IsValid(cachedCharacter) then return end
    local charPhysicsComponent = cachedCharacter:GetComponentByClass(UE4.UMoeCharPhysicsComponent)
    if charPhysicsComponent then
        charPhysicsComponent.bForceDisablePhysics = false
        charPhysicsComponent:SetMeshPhysicsEnable(true)
        charPhysicsComponent.bEnablePhysics = true
    end
end)
```

### 8.2 换装重建 AnimInstance 的竞争处理

玩家换装会触发 `AnimInstance` 重建，新实例 `IsUse2Bodytype` 默认为 false，导致二头身视觉瞬间消失。

**解法：监听换装前后两个事件，保证效果连续：**

```lua
function BP_Buff_ChiikawaBodyType:ReceiveInit()
    -- 换装前：将 IsUse2Bodytype 先置 false（防止旧值污染新 AnimInstance）
    _MOE.EventManager:RegisterEvent(
        _MOE.EventEnum.OnBeforeRefreshAnimInstance, self,
        self.OnBeforeRefreshAnimInstance
    )

    -- 换装后：如果 Buff 仍在，重新将新 AnimInstance 的 IsUse2Bodytype 置 true
    _MOE.EventManager:RegisterEvent(
        _MOE.EventEnum.OnRefreshAnimInstance, self,
        function(self, UID, BodyType)
            -- 只处理自己的角色，且体型非 Chiikawa 时才需要重设
            if self.Target and UID == self.Target:GetUID()
                and BodyType ~= UE4.EMoeBodyType.Chiikawa then
                self:ReceiveOnAddBuff()  -- 重新触发，让新 AnimInstance 生效
            end
        end
    )
end
```

## 十三、技术难点与踩坑记录

### 13.1 UGC 对象池 × UnLua 反射 × C++ UPROPERTY 三重冲突

**场景：** 平底锅作为 UGC 道具被对象池反复复用，Lua `ReceiveEndPlay` 调用 super 时通过 UnLua 反射将 `UPROPERTY(Instanced)` 成员置 nil，导致 Actor 复用时 C++ `ResetToDefault` 空指针崩溃。

**解法：** 子类刻意跳过 super `ReceiveEndPlay`，手动执行必要清理逻辑，跳过危险的三个 nil 赋值。

**经验：** 在 UnLua 环境下，对 C++ 侧 `UPROPERTY(Instanced)` 指针成员执行 Lua nil 赋值时需谨慎；在对象池/复用场景下尤其危险，需通过子类覆写隔离。

### 13.2 快速连击导致 Timer 覆盖与命中丢失

**场景：** 平底锅 CD 仅 0.5s，快速连续使用时，若用单一 Timer 句柄存储，后一次 `AddTimer` 覆盖前一次句柄，前一次命中的延迟 callback 既不会执行（命中丢失）也不会被 Remove（潜在内存泄漏）。

**解法：** 改用 `table` 数组缓存所有 Timer 句柄，`ReceiveEndPlay` / `ClearAllCachedTimers` 时统一遍历清理；每个 Timer 闭包内独立捕获当前帧对象，防止野指针。

### 13.3 拍扁期间物理系统竞争

**场景：** 多个系统（动画事件、碰撞、其他 Buff 等）会在运行时重新开启物理，单次关闭不能持久。

**解法：** Loop Timer 每 0.5s 强制关闭一次；退出拍扁后延迟 3s 再次双保险恢复，确保物理状态正确同步到所有客户端。

### 13.4 二头身 AnimInstance 重建竞争

**场景：** 玩家换装触发 `AnimInstance` 重建，新实例 `IsUse2Bodytype` 默认 false，Buff 期间换装后二头身视觉瞬间消失。

**解法：** 监听 `OnBeforeRefreshAnimInstance`（重建前先置 false，防旧值污染）和 `OnRefreshAnimInstance`（重建后如果 Buff 仍在则重新置 true）两个事件，确保换装后效果连续。

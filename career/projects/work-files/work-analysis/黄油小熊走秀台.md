## 工作内容拆解

### 1. NPC 走秀调度系统（客户端时间戳驱动 + 中途进度对齐）

- **主题时间表驱动**：从 `ResButterBearNPCZouXiu` 读取各主题走秀配置（`npcZouXiuStartTime` 起始时间戳、NPC id 列表、走路动作、定点 pose）；`CheckInWhichNPCZouXiu` 用 `HeartBeatModel:GetServerTime()` 判断"当前时间落在哪个主题的 [start, end) 区间"。`[一手]`
- **精准调度**：命中主题后计算 `nextStartTime = end - now` 起一个定时器，主题结束时自动再次 `CheckInWhichNPCZouXiu` 切下一场；无正在进行主题时 `FindCloestNPCZouXiu` 找最近一场并定时到点开演。`[一手]`
- **中途进场进度对齐**（`SatrtNPCZouXiuInMiddle` + `FindNPCStartTransform`）：新玩家进广场时若某场走秀已进行到一半，根据 `timePassed = now - startTimeStamp` + In/Out 速度反推 NPC 当前应在的**点位/朝向/所处阶段（In/ShowTime/Out）/剩余表演时长**，直接 `SpawnNPC` 到正确位置并进入对应阶段，而非从头播放。`[一手]`
- **单人/双人/黄油小熊差异**：`PlayerTypeEnum` 区分单人、双人并排（单动作/双人动作）、双人叠合（抱着/拖着）；黄油小熊为唯一 NPC id 映射，走路速度/停留时长单独配置。`[一手]`
- **死循环保护**：`isCheckingNPCZouXiu` 标志防止调度递归重入。`[一手]`

### 2. NPC/角色走秀三段式状态机（`BP_ButterBear_CharacterZouXiuComponent`）

- **三阶段**：`In`（点位1→表演点位）→ `ShowTime`（定点 pose）→ `Out`（表演点位→退场点位），点位数为奇数、表演点位取中点 `floor(endIndex/2)+1`。`[一手]`
- **平滑移动**：用 `UCharSmoothMoveComponent:SmoothMoveToV2` 按点位逐段行走，`OnCharacterSmoothMoveFinish` 回调推进到下一点位；到表演点位切 ShowTime、到退场点位 `DestroyNPC`。`[一手]`
- **速度换算**：`CalculateSpeedAndTime` 按"点位总距离 / 阶段时长 / 最大跑速"算出 In/Out 速度比，用 `ChangeFloatAttributeByName("MaxWalkSpeed", ratio)` Buff 精确控制走完全程用时 = 策划配置时长。`[一手]`
- **动画分层**：走路阶段 `PlayUpperBodyBlendAnim`（上半身混合 `BlendTwoHands` + `PlaySlotAnimationAsDynamicMontage("HandAction")`，可边走边飞吻/挥手）；表演阶段 `PlayFullBodyAnim`（全身 pose，蒙太奇/动画自适应）。`[一手]`
- **黄油小熊撒糖动作编排**：ShowTime 期间黄油小熊播撒糖动画（`AS_CH_Butterbear_SaTang`），按 `distributeCandyAnimLength` 调度"撒糖→定点 pose→第二次撒糖"，与 DS 侧糖果生成时间对齐。`[一手]`
- **NPC 形象与体型**：`SetAvatarInfo` 用 `ResButterBearNPCAvatarInfo` 覆盖 NPC 时装；黄油小熊 `CharScale=2` 放大；同时禁用抓取/潜水/道具/推挤等能力（霸体 Buff）。`[一手]`

### 3. 玩家走秀 Action State（`MoeCharActionStateCommonZouXiu`，DS 权威）

- **注册为通用子动作状态**：`MoeCharActionStateCommon.lua` 注册 `ECommonActionName.ZouXiu → MoeCharActionStateCommonZouXiu` + StateData 蓝图 `BP_StateData_ZouXiu`，进入走 `TryEnterActionState(ActionCommon)`。`[一手]`
- **霸体处理**：进入即置 `CanGrab/CanBeGrab/CanDive/CanPickProp/CanUseProp/CanShowProp/CanEnterBodyCollision/CanBePush=false`、`ForbiddenAddForce=true`，防止走秀被其他玩家打断（对应 bug 修复"被强控还能自由操作"）。`[一手]`
- **同款三段式**：客户端 `EnterZouXiuStateIn/ShowTime/Out` + `CalculateSpeedAndTime` 复用点位数组，走秀走路动画替换 + 走位平滑移动，到退场点位派发 `OnEndZouXiuAndBeforeCloseWindow` + `FinishPlayerZouXiuAndSendYaoQingHan`（致谢函）。`[一手]`

- **埋点**：本地玩家进入即 `ReportButterBearJoinCatwalk`。`[一手]`

## 技术点

### [网络架构] DS 权威 + 客户端表现分离，走秀/喝彩/撒糖多端一致
- 玩家走秀 Action State 以 DS 为权威（准入校验、舞台特效触发、传送退场都在 DS），客户端负责走位表现与动画；喝彩历史、撒糖生成、上台队列均在 DS `BP_ButterBearGP` 统一管理，通过多播 RPC（`DS2CMulti_UpdateCheerPanel` / `CallMultiRPCToAll_Custom`）广播给全端。

### [时间同步] 服务器时间戳驱动的走秀调度 + 中途进度对齐
- NPC 走秀调度不依赖后端接口，纯客户端基于 `HeartBeatModel:GetServerTime()` / DS `GetDSTime()` 判断主题区间；中途进场用 `timePassed` 反推 NPC 应处的点位/阶段/剩余时长（`FindNPCStartTransform`），保证任意时刻进广场看到的演出进度一致；撒糖时间戳同样基于服务器时间，支持改时间重算。

### [3C-角色 / 动画] 三段式走秀状态机 + 分层动画 + BlendSpace 热替换
- 复用一套三段式（In/ShowTime/Out）状态机同时驱动 NPC、黄油小熊、玩家；走路阶段上半身混合动作（可边走边玩梗）、表演阶段全身 pose；行走动画通过 `SeasonMoveBlendSpace` 机制热替换默认跑步 BlendSpace，节日结束即还原。
- **动画分工原则**：需要随移动实时驱动的"走姿"用 BlendSpace 替换（`ReplaceCommunitySeasonMoveBlendSpace`）；固定表演片段用 Montage 叠加——上半身玩梗 `PlaySlotAnimationAsDynamicMontage("HandAction")`、定点 pose `Montage_Play`。

### [引擎 / 动画底层] SeasonMoveBlendSpace：AnimBP 变量热替换实现走秀走姿（深挖）
> 对应资产 `Content/LetsGo3C/Assets/Base/Character/Animation/ABP_CH_GameCharacter.uasset`（347 节点 / 41 状态机，原生父类 `UMoeCharacterAnimInstance`）。`[一手]`

- **核心思想**：AnimBP 的移动状态（`OnGround → WalkAndRun` 内的 `AnimGraphNode_BlendSpacePlayer`）采样的 BlendSpace **是一个变量 `BSBaseMove`（`UBlendSpace1D*`，来自 C++ 父类）而非固定资产**，播放位置 X 由角色地面速度驱动。因此运行时改写该变量指向的资产，下一帧移动状态即采样到新 BlendSpace——无需改图、无需切状态、无需重进动画即可"热替换"。这也是走秀走姿能**随速度自适应、真实位移不打滑**的原因（走的仍是 Locomotion 速度混合链路，只换了采样资产）。
- **三层 C++ 实现**：
  1. 组件层 `UMoeAnimStateComponent` 持有 `TArray<FString> SpecialMoveBlendSpaceNames` + `ChangeSpecialMoveBlendSpace(add/remove)` / `GetSpecialMoveBlendSpaceByName`（后者经 `UMoePathTableHelper::GetBlendSpaceInfo` 从配表按 key 加载资源 → "策划可配置"来源）。
  2. AnimInstance 层 `UpdateBSBaseMoveByAvatarType` / `UpdateBaseMoveByAvatarType` 决定 `BSBaseMove` 指向：**第一优先**判断 `SpecialMoveBlendSpaceNames` 非空则取 `[0]`、`SetBSBaseMove(配表资源)` 并 `return`（优先级高于手持道具 BlendSpace、时装移动动画）；命中后 `CancelAsyncLoadAnimRes` 防在途换装动画覆盖。
  3. `SetBSBaseMove` 改写 AnimBP 绑定的变量；列表清空后 `ReplaceBSBaseMove` 按柔软度/时装/默认体型回退，保证退出走秀走姿正确复原。
- **Lua 封装 + 调用**：`LobbyUtils.ReplaceCommunitySeasonMoveBlendSpace(char, isAdd, moveKeyName)` = `ChangeSpecialMoveBlendSpace` + `UpdateBaseMoveByManual`（立即重刷，否则等下次刷新才生效）。进入走秀 `isAdd=true` 塞 `"Butterbear_Walk"` + 体型后缀（`GetAnimSuffixOfBodyType`，区分二头身）、退出 `isAdd=false` 移除；双人叠合从 KV 取 `DoubleAbstract_Walk_*`。调用点：`MoeCharActionStateCommonZouXiu.lua`（玩家）、`BP_ButterBear_CharacterZouXiuComponent.lua:SetBlendSpace`（NPC/小熊）、`ButterBearGPModel.lua`（双人）、`GMCommunityCommands.lua`（自测）。`[一手]`
- **设计取舍**：相比"Montage 覆盖"（打滑、占 slot、与上半身玩梗冲突）与"在公共 AnimBP 加走秀专用分支"（每个节日改公共图、回归风险高、不可配置/热更），本方案 **AnimBP 零改动 + 配表 key 驱动 + 进出对称可还原**，后续节日特殊行走可复用。
- **相关代码**：`Plugins/MOE/.../MoeAnimStateComponent.h:148 / .cpp:148,180`、`.../MoeCharacterAnimInstance.cpp:UpdateBSBaseMoveByAvatarType:888 / SetBSBaseMove:1722 / ReplaceBSBaseMove:706`、`LobbyUtils.lua:1265`。`[一手]`

### [运动控制] 距离/时长反算速度，精确匹配策划配置节奏
- `CalculateSpeedAndTime` 用"点位总距离 ÷ 阶段时长 ÷ 最大跑速"求速度比，配合 `SmoothMoveToV2` 逐段走位，保证 In/ShowTime/Out 各阶段耗时严格等于策划配置（解决 NPC 滑步、走不够时长等一系列表现 bug）。

### [并发/健壮性] 上台准入并发锁 + 状态兜底
- `DSCheckIfCanEnterPlayerZouXiu` 并发锁 + 防死锁定时器 + 两段式校验，避免多人同时报名导致的竞态（对应 bug"两名玩家同时上台"）；Action State `totalTime+5` 兜底定时器保证一定能退出走秀。

### [可维护性] 全 KV 配表驱动，策划可热更
- 各阶段时长、走路速度、撒糖数量/间隔、喝彩特效阈值、见面会 CD/权重、BlendSpace key、动画资源等均走 `ButterBearActivityClientKVConf`（KV 杂项表）等配表，发布后可后台热更、不出包。

## 难点与解决方案

- **NPC 走秀中途进场进度对齐**：玩家随时进广场，NPC 可能演到一半。→ 依服务器时间戳 `timePassed` + 速度反推 NPC 当前点位/朝向/阶段/剩余时长，`SpawnNPC` 到正确位置直接进对应阶段，避免从头重播。`[一手]`
- **走秀各阶段节奏与策划配置对齐**：走位耗时必须 = 配置时长。→ 距离÷时长反算速度比，`SmoothMoveToV2` 逐段行走（修掉滑步、动作没播完就消失、循环第二次特效消失等系列 bug）。`[git]`
- **多人同时报名竞态**：并发进入舞台导致状态错乱。→ DS 准入并发锁 + 防死锁定时器 + 两段式校验。`[一手]`
- **撒糖与黄油小熊撒糖动作时间不同步**：糖果生成需卡在小熊撒糖动作节点。→ DS 撒糖定时器与角色组件撒糖动画均基于服务器时间戳编排，改时间时重算（修 148466780/148286050 等）。`[git]`
- **走秀期间被打断/被强控还能操作**：走秀需完全霸体。→ Action State 进入即批量禁用抓取/潜水/推挤/加力等能力（修 148421206 系列、"被强控还能自由操作"）。`[git]`
- **见面会断线重连异常**：重连后交互页残留、无法移动视角、被抱起点同意无效。→ 修复重连事件重注册与交互状态清理（148096328/148371531/148423634）。`[git]`
- **手持物与喝彩按钮冲突/交互按钮被小火车按钮覆盖**：现网多按钮叠加。→ 调整按钮优先级/显隐（148754615/148100730）。`[git]`

## 工作内容拆解

### 1. 乐器彩蛋系统（story=128057708）

- 演奏台上悬挂 7 个乐器，玩家走进碰撞范围即触发对应音效。
- 乐器 ID 与音效 ID 通过配表解耦（`XiongChuMoActivityClientKVItem` KV 表，key=`instrument_{id}`），音效通过 `_MOE.SoundMgr:ReceivePlaySfx` 在**本地客户端**播放（空间音效，`bAttached=true`）。
- 碰撞回调 `Bp_OnEnterOverlapImp`：仅本地角色触发，通过 `Client2DSRPCEx("XiongChuMo_PlayInstrument", instrumentId)` 发 C2DS RPC，DS 广播给所有客户端（事件 `XiongChuMoPlayInstrument`），各端乐器组件收到事件后在本地播放音效。
- **演出期间静音**：收到播放事件时先查 GP Actor 的 `GetNPCState()`，若为 `ShowTime` 则静默跳过——防止乐器音效与演出音乐产生干扰。`[一手]`

### 2. NPC演出调度系统（story=128057707）

- **DS 侧调度**（每秒 tick，精准触发）：`InitShowTimeScheduler` 记录 `lastShowCheckTimestamp / nextShowTimeTimestamp`；`TickShowTimeScheduler` 每秒判断 `lastTime < targetTime <= currTime`，满足则 `EnterShowTimeOnDS`，并推算下次时间戳（`GetNextShowTimeTimestamp`，30min 对齐 + 可选延迟配置）。
- **DS 启动进度对齐**：`CheckAndEnterOngoingShowTimeOnDS` 在 DS 初始化时一次性检测"当前是否处于演出时间槽内"（`elapsed < duration`），若是则以剩余时长 `remaining` 作为演出时长参数，避免 DS 重启时演出从头播放。`[一手]`
- **配置表驱动**：演出时长、演出序列、音效 ID 均来自 KV 配表（`XiongChuMoActivityClientKVItem`），延迟偏移来自 `XiongChuMoNPCShowTimeDelayConfig`，支持后台配置调整而不重新出包。`[一手]`
- **客户端进度对齐**（`BuildShowTimePlaybackInfo`）：通过服务器时间计算 `elapsed = now - slotTimestamp`，得到 `playbackStartTime + remainingDuration`，让新进入玩家或切后台回来的玩家的 LevelSequence 从**正确进度**开始播放，而非从头。`OnEnterForeground` 也会重触发此逻辑。`[一手]`
- **LevelSequence 播放**（`PlayShowTimeLevelSequence`）：通过 `SetPlaybackPosition` 跳帧到 `playbackStartTime`；同步 Seek 音效播放位置（`UAkGameplayStatics.SeekPlayPosition`），保证音视频对齐。`[一手]`
- **演出 NPC 可见性管理**：演出时隐藏待机点三人组（缓存可见性快照）、显示木牌；演出结束时 `RestoreShowTimeNPCs` 恢复，干净无残影。`[一手]`
- **GM 调试工具套件**：`GMForceShowTime / GMSetShowTimeTimestamp / GMAdvanceShowTimeSeconds / GMSetShowTimeDuration / GMSetShowTimeIntervalDuration / GMResetShowTimeOverrides / GMLogShowTimeInfo`，均支持客户端 → DS `Client2DSRPCEx` 转发，方便 QA 在任意客户端执行。`[一手]`

### 3. 三人组 NPC 状态机（story=128057706）

- DS 权威状态（Replicated `NPCState`）：`Idle / Eating / ShowTime` 三态。`[一手]`
- **互斥表**（`NPCStateMutexTable`）：同态不可重入，异态按策划规则允许/拒绝切换，保证演出中 NPC 不会被提交食物打断。`[一手]`
- `DSCheckIfCanEnterNPCState(state)` → `SetNPCState` → `DSSetNPCState`（蓝图 Replicated 属性赋值）→ `OnRep_NPCState` 触发客户端响应（`OnEnterShowTime / OnExitShowTime`）。`[一手]`
- 演出结束后由 `StartShowTimeDurationTimer` 定时回调 `DSCheckIfCanEnterNPCState(Idle)`，不依赖客户端回报。`[一手]`

### 4. 食物效果系统（story=128057701/128057702/128057685）

### 5. 烹饪流程（镜头切换 / LevelSequence / 霸体）

- 玩家选完三种食材点击「开始制作」后，触发烹饪 LevelSequence：镜头切到烹饪锅固定视角，播放炒菜场景动画；烹饪期间玩家处于**霸体状态**（不可主动操作也不可被其他玩家交互）。`[一手确认]`
- `RepeatPlayCookProcessLevelSequence`：非烹饪时烹饪锅循环播放默认 idle 动画（每 30s 一次），进入烹饪时打断循环、播烹饪序列，播完后通过回调重启循环——烹饪锅始终保持动态表现。`[一手确认]`
- `SetShouTuiCheCookingState`：手推车在烹饪进行中设置为「烹饪中」状态，防止玩家二次触发交互。`[一手确认]`

### 6. 三人组交互组件（NPC 状态拦截 / 霸体 Buff）

- `BP_IA_SanRenZuInteractionComponent` 挂在三人组 NPC 所在区域，负责**进入/离开/点击**三个交互回调。`[一手确认]`
- **进入区域时**给角色添加 `BP_Buff_SuperArmor` 霸体 Buff（`ClientAddBuffWithCustomParam`），防止玩家在提交菜品对话期间被其他玩家打断。`[一手确认]`
- **离开区域时**移除霸体 Buff、派发 `PlayerLeaveSanRenZu` 事件（触发关闭做菜相关 UI），并通过 `HookMixin` 触发 `OnPlayerLeaveSanRenZu` 钩子供扩展使用。`[一手确认]`
- **点击按钮时** `CheckIfCanClickButton` 先做双重拦截：角色非 Idle 状态弹 toast；NPC 处于 `ShowTime` 或 `Eating` 状态弹 toast（"光头强和熊大熊二正在享用其他星宝的美食，请稍后再来~"），均通过后才调 `BearCookModel:OpenCookSubmitView` 弹出提交界面。`[一手确认]`

### 7. NPC 吃食物表现（配表驱动）

- `NPCEatingAnimation(itemId)`：先统一播三人组进食动画（`PlayNPCAnimation` 清理旧定时器、设 `m_SkipTick=true` 防止 NPC idle 逻辑干扰动画），动画结束后回调 `OnNPCEatFood`。`[一手]`
- `OnNPCEatFood(itemId)`：从 `XiongChuMoNPCFoodReactionConfig` 读取三个角色各自的 animation/soundEffect/bubbleText，用 `;` 分割后一一驱动（动画/音效/气泡）；**黑暗料理特殊逻辑**：光头强动画结束后延迟显示头顶情绪气泡 `ShowGuangTouQiangBubble`。`[一手]`
- 气泡计时器统一存入 `BubbleTimers` 数组，`CleanTimer / ReceiveEndPlay` 时全部清理，防止内存泄漏。`[一手]`

### 6. 玩家吃食物表现

- `CharacterEatingAnimation(itemId, UID)`：检查是否处于形变 buff（`Moe.Buff.ShapeShift`）选不同动作，暂时 `SetHandHoldVisibility(false)` 隐藏手持物（对应 bug=151118093 "拥有手持物提交菜品没有吃菜品动作"），动画完成后通过 `C2DS_AddProp` 给玩家发道具。`[一手]`

## 技术点

### [网络架构] 客户端-DS 双端协作，NPC 状态 Replicated 属性驱动客户端表现

- 所有 NPC 状态以 DS 为权威，通过 `NPCState`（蓝图 Replicated 属性）同步；客户端通过 `OnRep_NPCState` 响应，无需额外 RPC 轮询。
- 演出调度纯 DS 侧 timer 驱动（1s tick），不依赖服务器接口——在广场这种无需服务器记录的场合降低后端压力。
- 乐器触发走 C2DS → DS多播 路径，保证所有玩家听到同一音效。

### [时间同步] 演出进度基于服务器时间戳计算，中途进场/切后台均对齐

- DS 端以 `_MOE.CommunityDSManager:GetDSTime()` 或 `UMoeTimeLibrary.GetUtcTimeSeconds()` 作为时间源；客户端用 `HeartBeatModel:GetServerTime()`，接口统一在 `GetCurrentServerTimestamp`。
- `BuildShowTimePlaybackInfo` 计算 `elapsed = now - slotTimestamp`，映射到 LevelSequence 的 `SetPlaybackPosition`，并用 `SeekPlayPosition` 对齐 Wwise 音效，确保中途进入的玩家看到的视听内容与序列进度一致。

### [容错与边界] DS 重启后的演出续播

- DS 重启时 `CheckAndEnterOngoingShowTimeOnDS` 主动检测"当前时间是否处于演出槽内"，是则以**剩余时长**为参数发起演出，避免新 DS 的调度器等到下一个槽才触发。
- 演出时长上限兜底：`timerDuration <= 0` 时保底 `0.01s`，防止定时器异常。

### [性能] 星宝饼干泡泡性能权重管理

- DS 端通过 `DSRece_XingBaoBiscuitSpawnBubble_RemovePerfWeight` 在泡泡销毁时释放性能配额，配合上限检测防止广场中泡泡数量无限膨胀（对应 bug=151118093 修复）。

### [可维护性] 全配表驱动，策划可热更

- 演出时长、序列名、音效 ID、乐器音效 ID 均走 `XiongChuMoActivityClientKVItem` KV 表；NPC 对每种食物的动画/气泡/音效来自 `XiongChuMoNPCFoodReactionConfig`；延迟偏移来自 `XiongChuMoNPCShowTimeDelayConfig`——发布后可后台热更，不出包。

## 难点与解决方案

- **演出进度跨越 DS 重启**：DS 掉线重启后演出应从剩余进度开始，而非从头。 → 利用 UTC 时间戳对齐，`CheckAndEnterOngoingShowTimeOnDS` 计算 elapsed < duration 则续播剩余时长，DS 重启对玩家无感知。`[一手]`
- **中途进场/切后台后序列进度对齐**：视频 + 音频均需从正确帧开始。 → `BuildShowTimePlaybackInfo` 计算进度，`SetPlaybackPosition` 跳帧，`SeekPlayPosition` 对齐 Wwise 音效时间轴。`[一手]`
- **NPC 动画被 IdleShow 逻辑干扰**：播进食动画期间 NPC 的 idle 控制逻辑会重置动画。 → `m_SkipTick = true` 在动画期间跳过 tick，动画结束后清除标记。`[一手]`
- **星宝饼干泡泡无限堆积**（bug=151118093）：泡泡性能权重未释放 + 无玩家进入时泡泡不销毁。 → `HandHoldSummonedBubbleXiongChuMo` 增加最大生命周期计时器 + `ReceiveEndPlay` 释放 DS 端性能权重配额。`[一手]`
- **拥有手持物时提交菜品动画被遮挡**（bug=151118093）：吃菜动作期间手持物可见，遮挡动画表现。 → 动画开始前 `SetHandHoldVisibility(false)`，动画结束后恢复。`[一手]`
- **提交菜品给NPC后无响应**（bug=154088107, S17）：线上 RPC 流程断链。 → 排查 C2DS → DS Check → DS2C 多播 的完整链路，定位并修复。`[git]`
- **传送时玩家朝向不变**（bug=150642990）：传送落点的 Yaw 未跟随目标。 → 修复传送接口的朝向参数。`[git]`

### Q4. RPC 可靠实现原理（reliable 底层机制）

| 维度 | 内容 |
|------|------|
| 暴露的问题 | 只了解使用场景，不清楚 UE 底层如何保证 reliable RPC 的送达。 |
| ⚠️ 不足 | 你简历写了"多方向 RPC 通道设计"，被追问底层实现却答不上，属于"用过没抠原理"的典型减分点。 |
| 📌 参考方向 | UE RPC 走 **NetDriver → UNetConnection → UChannel（ActorChannel）**。Reliable 与 unreliable 分别用独立序号：**reliable RPC 带递增序号，缓存在 OutRec 重发队列中，未收到 ACK 会重传，接收端按序号排序保证顺序与不丢失**；unreliable 不重发、可丢弃。要点：可靠 RPC 有队列上限（RELIABLE_BUFFER，溢出会断连）、reliable 保证"顺序 + 送达"、底层基于 UDP 自建可靠层（非 TCP）。还需讲 RPC 三种类型（Server/Client/Multicast）与调用权威端要求。 |
| 📚 加强学习 | ①读源码：`UActorChannel::ReceivedBunch`、`UChannel::SendBunch`、`UNetConnection` 的 OutRec/InRec；②整理"UE 如何在 UDP 上实现 reliable"一段话；③对比 TCP 可靠性与 UE 自建可靠层的差异（为何不直接用 TCP）。 |

### Q5. IK 底层逻辑

| 维度 | 内容 |
|------|------|
| 暴露的问题 | 只知道用 Two Bone IK 节点，没研究过底层实现。 |
| ⚠️ 不足 | 讲不清 IK 的数学/算法，属于动画方向的深度缺口。 |
| 📌 参考方向 | **正向运动学（FK）**：由骨骼旋转推末端位置；**反向运动学（IK）**：由目标末端位置反解骨骼旋转。常见算法：**Two Bone IK（解析法，用余弦定理直接求两骨夹角，常用于脚/手）**、**FABRIK（迭代法，前后两遍逼近，适合多骨链）**、**CCD（循环坐标下降）**。UE5 引入 **Control Rig + Full Body IK（基于 Position-Based IK 求解器）**。脚步 IK 还涉及地面射线检测 + 骨盆下沉。 |
| 📚 加强学习 | ①手推 Two Bone IK 的余弦定理解法；②理解 FABRIK 迭代过程；③在 UE5 里用 Control Rig 做一次脚步 IK，把"射线检测地面 → 调整脚骨 → 骨盆补偿"讲清。 |

### Q6. VAT 技术（顶点动画纹理）

| 维度 | 内容 |
|------|------|
| 暴露的问题 | 忘记 VAT 的具体概念和作用（面试中称"虚拟纹理动画"，实为 **Vertex Animation Texture 顶点动画纹理**）。 |
| ⚠️ 不足 | 概念记混，且与"虚拟纹理 Virtual Texture(VT)"混淆——两者完全不同。 |
| 📌 参考方向 | **VAT（Vertex Animation Texture）**：把顶点动画数据（每帧每个顶点的位置/法线偏移）**烘焙进纹理**，运行时由顶点着色器采样纹理驱动顶点位移，从而在 GPU 上播放动画，**无需骨骼/CPU 蒙皮**。用途：海量同屏对象动画（人群、鱼群、大规模植被、机械/柔体动画），大幅降低 CPU 开销，配合 GPU Instancing 效果极佳。代价：显存占用、不易做混合、灵活性低于骨骼动画。**注意区分 Virtual Texture（VT，纹理流送/按需加载的显存管理技术）**。 |
| 📚 加强学习 | ①明确 VAT vs 骨骼动画 vs Virtual Texture 三者区别（面试极易被混问）；②在 UE 用 Houdini/内置工具烘焙一次 VAT 跑人群；③联系你简历"粒子→Mesh 曲线/动画驱动轨迹重构"，讲清何时该用 GPU 驱动动画。 |

### Q7. 虚幻垃圾回收机制（GC）

| 维度 | 内容 |
|------|------|
| 暴露的问题 | 把 **UE 的标记-清扫 GC** 与 **Lua 的分代/三色标记 GC** 混淆了。 |
| ⚠️ 不足 | 两套 GC 机制答串，说明理解停留在名词层面。 |
| 📌 参考方向 | **UE GC**：基于 **Mark-Sweep（标记-清扫）**，只管理 `UObject`。通过 `UPROPERTY`/`TObjectPtr`/根集（Root Set，`AddToRoot`）构建**引用图**，从根可达的对象存活，不可达的被清除；UE5 有**增量式 GC（Incremental GC）**分帧执行降低卡顿。关键：非 UPROPERTY 的裸指针不被追踪（易野指针/被回收）。**Lua GC**：早期是**增量三色标记-清扫（白/灰/黑三色）**，Lua 5.4 引入**分代 GC（generational）**——新对象死得快，分年轻代/老年代减少全量扫描。二者都是可达性分析，但 UE 只管 UObject、Lua 管所有 GC 对象；"分代/三色"是 Lua 的，不是 UE 的。 |
| 📚 加强学习 | ①做一张对照表：UE Mark-Sweep vs Lua 三色/分代；②理解 UE UPROPERTY 追踪机制与 TWeakObjectPtr/TStrongObjectPtr；③结合 UnLua：UE 对象与 Lua 对象跨语言引用如何避免误回收（UnLua 的对象绑定与生命周期）。 |

### Q8. 碰撞检测底层算法

| 维度 | 内容 |
|------|------|
| 暴露的问题 | 只了解上层使用（Overlap/Hit/通道），不清楚几何体相交判断的底层实现。 |
| ⚠️ 不足 | 你简历有"弹道与命中判定""服务器权威命中判定"，被问几何相交底层却答不出。 |
| 📌 参考方向 | 两阶段：**Broad Phase（粗筛）**用 **AABB + 空间划分（BVH / Sweep and Prune / 网格）**快速排除不可能相交的对；**Narrow Phase（精筛）**做精确相交，核心算法 **GJK（判断凸体是否相交，基于 Minkowski 差 + 单纯形）** 与 **EPA（求穿透深度/法线）**、**SAT（分离轴定理，凸多边形）**、球/胶囊/盒的解析相交。射线检测用 **Ray-AABB slab 法、Ray-Triangle（Möller–Trumbore）**。UE5 物理引擎 **Chaos**（旧为 PhysX）负责这些。还涉及 **CCD（连续碰撞检测，防高速穿模）**。 |
| 📚 加强学习 | ①吃透 AABB 相交、SAT、GJK 三个核心（GJK 是重点）；②理解 Broad/Narrow 两阶段与 BVH；③把你的"子弹命中判定"用 LineTrace/Sweep 的原理讲清，并说明服务器权威判定为何要 CCD。 |

### Q10. 模拟端平滑处理（其他玩家移动的低延迟平滑）

| 维度 | 内容 |
|------|------|
| 暴露的问题 | 无法准确回忆并说明模拟端（Simulated Proxy）其他玩家移动位置的低延迟平滑实现逻辑。 |
| ⚠️ 不足 | 你简历明确写了"位置插值的网络同步（dead-reckoning）"，这是你做过的核心内容，却没答好——属于**简历强相关点没准备好**，减分最重。 |
| 📌 参考方向 | UE 角色移动同步有三种角色：**Authority（服务器）/ AutonomousProxy（本地玩家，客户端预测 + 服务器校正 + 回滚重放）/ SimulatedProxy（其他玩家，仅收状态）**。模拟端平滑：`CharacterMovementComponent` 的 **NetworkSmoothing（Linear / Exponential）**——网络更新是离散低频的，直接跳会瞬移，所以把 Mesh 与胶囊体解耦，**用插值把 Mesh 平滑追赶到胶囊体的最新网络位置**；再叠加 **dead-reckoning（用上次速度外推预测当前位置）** 降低视觉延迟。关键词：`SmoothClientPosition`、`bNetworkSmoothingComplete`、插值时间 = NetUpdate 间隔。 |
| 📚 加强学习 | ①**必做**：把自己做过的位置插值组件重新梳理，准备一段 2 分钟讲解（三种 Proxy + 插值平滑 + dead-reckoning 外推）；②读 `UCharacterMovementComponent::SmoothClientPosition_Interpolate`；③区分"预测（自己）"与"外推/插值（别人）"两种平滑的本质差异。 |

## 专题：性能分析与 Trace（Unreal Insights）

**一句话定位**：能独立完成 抓 trace → 定位热点 → 埋点验证 的性能优化闭环，理解 UE trace 计时体系与 Lua/UnLua 特有开销。

### Trace 文件怎么生成（工作流）
- 启动参数决定一切（`FastBatch/RunLocalDS/.../RunLocalDS.*.bat`）：
  - `-Trace=cpu,frame,bookmark,LoadTime,memory,task,object`：选择开启哪些通道，不开的不产生数据也不拖慢游戏
  - `-tracefile`：写本地 `Saved/Profiling/*.utrace`；`-tracehost=127.0.0.1`：实时推给本机 Insights
  - `-statnamedevents`：把 stat 计数器镜像成 CPU 时间轴上的命名色块
  - `-moelua`：项目自定义，开启 Lua 相关采集
- 拉取：`FastBatch/Windows/PullUnrealInsightTraceFile.bat` 搬到 Insights 的 `TraceSessions`
- 分析：`Insight-UE4.bat` → UnrealInsights.exe → Timing Insights 视图

### trace 里每个 timer 的 4 种来源（核心认知）
1. **引擎自带 scope**：渲染 / Tick / GC / 物理路径引擎已预埋，无需自己加
2. **手动 stat 三件套**（走 stat 系统，可 `stat xxx` 实时看）：
   - `DECLARE_STATS_GROUP` + `DECLARE_CYCLE_STAT_EXTERN`（声明，起名字）
   - `DEFINE_STAT`（定义一次）
   - `SCOPE_CYCLE_COUNTER(STAT_xxx)`（函数体内埋点，RAII 记进出时间差）
   - 真实例：UnLua `STATGROUP_UnLuaOpt` / `STAT_UnLua_CallUE`（`UnLuaPrivate.h` + `FunctionDesc.cpp`），`#if STATS` 包裹，Shipping 无开销
3. **一次性命名 scope** `TRACE_CPUPROFILER_EVENT_SCOPE(名字)`：随手加、名字写死、只需 `-Trace=cpu`。真实例：`MoeMetricTrace/PerformDataInstanceSubsystem.cpp::Tick`
4. **动态命名 scope** `SCOPED_NAMED_EVENT_F("%s::%s", 类, 函)`：运行时拼名字。**满屏 Lua 函数 timer 的真正来源**——不是逐个手写，而是 UnLua 在 Lua↔UE 统一入口（`FunctionDesc.cpp` CallLua/CallUE）埋一次，所有调用共享

### Lua 层专用工具（3 套，用途不同）
- `FELuaMonitor`（`ProjectGLuaProfiler`）：`lua_sethook` 在每次进/出 Lua 函数回调，构建调用树，编辑器点按钮启动；`lua_setallocf` 统计 Lua 内存
- `MoeMetricTrace / UPerformDataInstanceSubsystem`：运行时每 30s 定时采集，`PerformanceData START/STOP` 控制台命令控制
- `UnLuaPerformanceTestProxy.lua`：微基准，跑 100 万次 `Seconds()` 掐表算单次纳秒——所有 profiler 的最底层原理（两个时间戳相减）

### 优化心法（面试可展开）
- **Inclusive vs Exclusive**：含子耗时看总占比，自身耗时（Exclusive）大才是本函数慢
- **卡顿(hitch) vs 均慢**：单帧超长看最宽帧（GC/加载/事件广播）；持续掉帧看每帧都在的大块
- **Lua 项目高频热点**：① Lua↔UE 跨语言调用固定开销（`CallUE`/`CallLua` 色块数量）② Tick 干重活 ③ 循环内属性访问（`PropertyVisit`）；对应编码规范里 local 缓存全局、`table.concat`、按需 require
- **先测量再优化**：改前改后各抓一次 trace 对比
